# 02. 서브쿼리 심화와 테이블 변경 (8주차 실습)

> 출처: `2026-2/데이터베이스설계/8주차 서브쿼리, 테이블 변경.pdf`
> 실습 과제(Q1~Q5)는 과제이므로 풀이는 싣지 않고, 필요한 개념만 정리함.

## 한눈에 보기
- **비상관 서브쿼리**: 안쪽 질의가 바깥과 독립 → 한 번만 실행
- **상관 서브쿼리**: 안쪽 질의가 바깥 행의 값을 참조 → 바깥 행마다 다시 실행
- **NOT EXISTS 이중 부정** = "모든 ~에 대해" (관계 대수의 나눗셈)
- `ALTER TABLE` 로 이름·컬럼·제약 변경

## 1. 실습 테이블
| 테이블 | 주요 컬럼 |
|---|---|
| EMPLOYEE | Id(PK), Name, Department, Budget |
| BOAT | Bid(PK), Bname, Color |
| SAILOR | Sid(PK), Sname, Rating, Age |
| RESERVE | (Sid, Bid)(PK, 각각 FK), Day |
| ARTIST | ArtistID(PK), LastName, FirstName, Nationality, DateOfBirth, DateDeceased |
| WORK | WorkID(PK), Title, Medium, Description, Copy, ArtistID(FK) |
| CUSTOMER | CustomerID(PK), Lastname, Firstname |
| CUSTOMER_ARTIST_INT | (ArtistID, CustomerID)(PK) — 고객이 관심 있는 작가 (교차 테이블) |

## 2. 비상관 vs 상관 서브쿼리
```sql
-- 비상관: 안쪽이 독립적으로 한 번 실행
SELECT Sname FROM SAILOR
WHERE Sid IN (SELECT Sid FROM RESERVE WHERE Bid = 103);

-- 상관: 바깥 W1 의 값을 안쪽에서 참조 → 중복 행 찾기
SELECT W1.Title, W1.Copy FROM WORK W1
WHERE W1.Title IN (SELECT W2.Title FROM WORK W2
                   WHERE W1.Title = W2.Title AND W1.WorkID <> W2.WorkID);
```

### 함수 종속성 검사에 쓰기
"Name → Department" 가 성립하는지: 같은 Name 인데 Department 가 다른 행이 있으면 깨짐
```sql
SELECT E1.Name, E1.Department FROM EMPLOYEE E1
WHERE E1.Department IN (SELECT E2.Department FROM EMPLOYEE E2
                        WHERE E1.Name = E2.Name AND E1.Department <> E2.Department);
```
(결과가 비어 있으면 종속성 성립. 같은 이름 'Adams' 를 다른 부서로 넣으면 결과가 나타남)

## 3. NOT EXISTS
### 여집합: 조인되지 않는 행
```sql
-- EMP 에 없는 사원(비정규직)이 대출한 책
SELECT L.Bname FROM LEND L
WHERE NOT EXISTS (SELECT * FROM EMP E WHERE L.Eid = E.Eid);
```
> "A.컬럼 = B.컬럼" 으로 조인했을 때 **짝이 없는(false)** A 의 행들

### 이중 부정 = "모든" (나눗셈) ⭐
"**모든 고객**이 관심을 가진 작가" = "관심을 갖지 **않은** 고객이 **없는** 작가"
```sql
SELECT A.FirstName, A.LastName FROM ARTIST A
WHERE NOT EXISTS (                       -- 이런 고객이 없어야 한다:
    SELECT C.CustomerID FROM CUSTOMER C
    WHERE NOT EXISTS (                   --   이 작가에게 관심 기록이 없는 고객
        SELECT CAI.CustomerID FROM CUSTOMER_ARTIST_INT CAI
        WHERE C.CustomerID = CAI.CustomerID AND A.ArtistID = CAI.ArtistID));
```
- 결과: ArtistID = 11 (Sargent) — 고객 1000, 1001, 1015 모두 관심

### MINUS (차집합) 로 같은 질의
```sql
SELECT A.FirstName, A.LastName FROM ARTIST A
WHERE NOT EXISTS (
    (SELECT C.CustomerID FROM CUSTOMER C)                 -- 전체 고객
    MINUS
    (SELECT CAI.CustomerID FROM CUSTOMER_ARTIST_INT CAI   -- 이 작가에 관심 있는 고객
     WHERE A.ArtistID = CAI.ArtistID));
```
> 전체 고객 − 관심 고객 = 공집합 ⇔ 모든 고객이 관심

## 4. 테이블 변경 (Oracle)
| 작업 | 문법 |
|---|---|
| 이름 변경 | `ALTER TABLE <테이블> RENAME TO <새이름>;` |
| 컬럼 추가 | `ALTER TABLE <테이블> ADD <컬럼> <타입> <조건>;` |
| 컬럼 타입 변경 | `ALTER TABLE <테이블> MODIFY (<컬럼> <타입> <조건>);` |
| 컬럼 삭제 | `ALTER TABLE <테이블> DROP COLUMN <컬럼>;` |
| 제약 추가 | `ALTER TABLE <테이블> ADD CONSTRAINT <이름> <제약>;` |
| 제약 삭제 | `ALTER TABLE <테이블> DROP CONSTRAINT <이름>;` |
| 기본값 | `ALTER TABLE <테이블> MODIFY (<컬럼> DEFAULT <값>);` |
| NULL → NOT NULL | `ALTER TABLE <테이블> MODIFY (<컬럼> NOT NULL);` (기존 NULL 이 있으면 실패) |

```sql
ALTER TABLE CUSTOMER RENAME TO CUSTOMER_VERSION2;
ALTER TABLE CUSTOMER ADD Address VARCHAR2(100);
ALTER TABLE ARTIST ADD CONSTRAINT BirthValuesCheck CHECK (DateOfBirth < DateDeceased);
```
- CHECK 제약 위반 삽입은 오류(ORA-02290), DEFAULT 는 컬럼을 생략하고 삽입할 때 적용

## 1. 현재 DB 분석 도구
### 상관 서브쿼리
| 일반 서브쿼리 | 상관 서브쿼리 |
|---|---|
| 아래에서 위로 한 번 처리 | **중첩 처리**: 위 질의의 행마다 아래 질의와 비교 |
| 보통 서로 다른 테이블 (ARTIST / WORK) | 같은 테이블을 양쪽에 (WORK W1 / WORK W2) |
- 가정한 제약이 실제로 지켜지는지 확인 (같은 Title 의 행, 함수 종속성 Department → DeptPhone 위반 등)
- 흔한 함정: 상관 조건(`W1.WorkID <> W2.WorkID`)을 빠뜨리면 자기 자신과 같다고 나옴

### EXISTS / NOT EXISTS
- **EXISTS**: 서브쿼리에 조건을 만족하는 행이 **하나라도** 있으면 참
- **NOT EXISTS**: **모든 행이** 조건을 만족하지 않을 때만 참
- **이중 NOT EXISTS** → "모든 행에 대해 ~인" 행 찾기 (모든 고객이 관심 있는 작가)

### 역공학 (Reverse Engineering, RE)
- DB 스키마를 읽어 **데이터 모델을 만들어 내는** 과정
- RE 모델은 재설계의 출발점. 개념 스키마도 내부 스키마도 아닌 중간 성격이고, **거의 항상 정보가 빠져 있어** 꼼꼼히 검토
### 의존 그래프 (Dependency Graph)
- 한 요소(테이블, 뷰, 트리거, 프로시저)가 다른 요소에 어떻게 의존하는지 그린 그림 → 변경 영향 범위 파악

### 백업과 테스트 DB
- 스키마 사본 3개: **작은 테스트 DB**(초기 테스트) → **큰 테스트 DB**(2차 테스트) → **운영 DB**

## 2. 테이블·열 변경
| 변경 | 방법·주의 |
|---|---|
| **테이블 이름** | 간단한 경우 외엔 좋은 명령이 없음 → 새 이름으로 재생성·테스트 후 옛 테이블 삭제. 영향이 커서 **별칭 뷰**를 쓰는 편이 낫다 (원본 이름이 바뀌면 뷰만 고침) |
| **NULL 열 추가** | `ALTER TABLE ... ADD 열 타입 NULL;` DEFAULT·UNIQUE 도 함께 가능. **새 DEFAULT 는 새 행에만 적용**, 기존 행은 NULL |
| **NOT NULL 열 추가** | ① NULL 로 추가 ② 모든 행에 값 채우기 ③ NOT NULL 로 변경 |
| **비키 열 삭제** | `ALTER TABLE ... DROP COLUMN` |
| **외래키 열 삭제** | 외래키 **제약 먼저** 삭제 |
| **기본키 삭제** | 그 키를 쓰는 **모든 외래키 먼저** 삭제 → 기본키 제약 삭제 |
| **타입·제약 변경** | `ALTER TABLE ... ALTER COLUMN` (Oracle 은 MODIFY). 데이터 손실·거부 가능. NULL → NOT NULL 은 모든 행에 값이 있어야 |
| 타입 변환 방향 | 구체적 타입(date, money, numeric) → char/varchar 는 **보통 성공**, 반대는 **문제될 수 있음** |
| 제약 추가·삭제 | `ALTER TABLE ... ADD / DROP CONSTRAINT` |

## 3. 관계 변경
### 최소 카디널리티
| 쪽 | 0 → 1 | 1 → 0 |
|---|---|---|
| **부모 쪽** | 외래키를 NULL → **NOT NULL** (모든 행에 값이 있어야) | NOT NULL → NULL |
| **자식 쪽** | 강제 **트리거 추가** | 트리거 삭제 |

### 최대 카디널리티
| 변경 | 방법 |
|---|---|
| **1:1 → 1:N** | 외래키가 올바른 테이블에 있으면 **UNIQUE 제약 제거**. 잘못된 쪽에 있으면 올바른 테이블로 옮기고 UNIQUE 를 안 붙임 |
| **1:N → N:M** | **새 교차 테이블**을 만들고 키·외래키 값을 그리로 옮김 |
| **N:M → 1:N** (축소) | 자식에 외래키를 만들고 교차 테이블에서 **값 하나만** 옮김 → **데이터 손실 가능** |
| **1:N → 1:1** (축소) | 외래키 중복 제거 후 **UNIQUE** 제약 |

### 관계 추가·삭제
- 추가: `CREATE TABLE ... FOREIGN KEY`. 기존 테이블이 새 테이블의 자식이면 기존 테이블에 외래키 제약 추가
- 삭제: **외래키 제약 먼저**, 그다음 테이블
- 비정규화를 위한 관계 추가·제거도 같은 방식

## 4. 순공학 (Forward Engineering)
- 데이터 모델 변경을 **기존 DB 에 적용**하는 과정 (역공학의 반대)
- 운영 DB 에 쓰기 전에 결과를 테스트. 도구가 실행할 SQL 을 보여 주면 **꼼꼼히 검토**

# 03. 저장 프로시저, 함수, 트리거와 수강신청 예제 (Part 8: 저장 프로시저 프로그래밍(3) + 10~12주차 실습)

> 출처: `2026-2/데이터베이스설계/08. PLSQL(3).pdf`, `10주차 PLSQL(1).pdf`, `11주차 PLSQL(2).pdf`, `12주차 PLSQL(3).pdf`
> 10~12주차 실습 자료는 강의 예제를 직접 실행하는 내용과 과제로 구성됨. 과제 문제·풀이는 싣지 않고 개념만 정리함.

## 한눈에 보기
| | 저장 프로시저 | 함수 | 트리거 |
|---|---|---|---|
| 실행 | `EXECUTE` 로 **명시적 호출** | 식 안에서 호출, **값 반환** | **이벤트(DML)** 가 일어나면 **자동** |
| 매개변수 | IN, OUT, IN OUT | **IN 만** | 없음 (`:old`, `:new`) |
| 반환 | OUT 매개변수로 | **RETURN 필수** | 없음 |

### 저장 프로시저·함수를 쓰는 이유
- 정보 **캡슐화**, 기능 **재사용**, **트랜잭션 제어**
- DB 에 **미리 컴파일**되어 저장 → 매번 변환하는 SQL 보다 빠름
- 문법 오류를 **실행 시간이 아니라 컴파일할 때** 잡음

---

## 1. 저장 프로시저
```sql
CREATE [OR REPLACE] PROCEDURE 이름 (매개변수 [IN|OUT|IN OUT] 타입, ...)
IS
    -- 지역 변수 (IS 와 BEGIN 사이, DECLARE 안 씀)
BEGIN
    ...
[EXCEPTION ...]
END;
/
```
| 모드 | 방향 | 실인자 |
|---|---|---|
| **IN** (기본, 생략 가능) | 호출자 → 프로시저 | 상수, 수식, 초기화된 변수 |
| **OUT** | 프로시저 → 호출자 | **초기화 안 된 변수** |
| **IN OUT** | 양방향 (받아서 바꿔 돌려줌) | 초기화된 변수 |

```sql
CREATE OR REPLACE PROCEDURE update_sal (v_empno IN NUMBER)
IS
BEGIN
    UPDATE emp SET sal = sal * 1.1 WHERE empno = v_empno;
    COMMIT;
END;
/
SHOW ERROR                 -- 컴파일 오류 확인
EXECUTE update_sal(7369);  -- 실행
DROP PROCEDURE update_sal; -- 삭제
```

## 2. 함수
```sql
CREATE [OR REPLACE] FUNCTION 이름 (매개변수 IN 타입, ...)
RETURN 반환타입
IS
    ...
BEGIN
    ... RETURN 값;          -- 적어도 하나의 RETURN
END;
/
```
```sql
CREATE OR REPLACE FUNCTION FC_update_sal (v_empno IN NUMBER) RETURN NUMBER
IS
    v_sal emp.sal%TYPE;
BEGIN
    UPDATE emp SET sal = sal * 1.1 WHERE empno = v_empno;
    COMMIT;
    SELECT sal INTO v_sal FROM emp WHERE empno = v_empno;
    RETURN v_sal;
END;
/
VAR salary NUMBER;                     -- 반환값 받을 바인드 변수
EXECUTE :salary := FC_update_sal(7900);
PRINT salary;
DROP FUNCTION FC_update_sal;
```
> ⚠️ DML(UPDATE)이 들어 있는 함수는 `SELECT FC_update_sal(7900) FROM DUAL` 처럼 SQL 문 안에서는 호출할 수 없다(ORA-14551). 위처럼 PL/SQL 이나 EXECUTE 로 호출한다.

## 3. 트리거
- DB 에 특정 변경이 가해지면 DBMS 가 **자동 호출**하는 프로시저. 프로시저·함수는 외부 명령으로, 트리거는 **트리거링 이벤트**로 실행
- 이벤트: 테이블에 대한 **INSERT, UPDATE, DELETE**. 테이블과 별도로 저장, **뷰가 아니라 테이블**에 정의(이 강의 범위)
- 구성: **사건(event)** → **조건(condition)** → **동작(action)**
```sql
CREATE [OR REPLACE] TRIGGER 이름
BEFORE | AFTER  INSERT [OR UPDATE] [OR DELETE]  ON 테이블
[FOR EACH ROW]
[WHEN (조건)]
[DECLARE ...]       -- 트리거에서 변수 선언은 DECLARE 사용
BEGIN ... END;
/
```
```sql
CREATE TRIGGER incr_count
BEFORE INSERT ON student          -- 사건
FOR EACH ROW
WHEN (new.age < 18)               -- 조건 (WHEN 절 안에서는 콜론 없이 new)
BEGIN                             -- 동작
    DBMS_OUTPUT.PUT_LINE('미성년자 : ' || :new.ename);
END;
```
- 용도: 참조·데이터 무결성 등으로 **표현 못 하는 복잡한 제약**, 작업 감시·보안, 변화에 따라 다른 프로그램 실행 (→ 최소 카디널리티 O-M 강제)

### 문장 트리거 vs 행 트리거
| | 문장 트리거 | **행 트리거** (`FOR EACH ROW`) |
|---|---|---|
| 실행 횟수 | 이벤트당 **한 번** | 영향받은 **행마다** |
| 행 값 제어 | 불가 | 가능 (`:old`, `:new`) |

| 이벤트 | `:old` | `:new` |
|---|---|---|
| INSERT | - | 넣을 값 |
| UPDATE | 바꾸기 전 값 | 바꿀 값 |
| DELETE | 지워질 값 | - |

```sql
CREATE OR REPLACE TRIGGER trigger_test
BEFORE UPDATE ON dept FOR EACH ROW
BEGIN
    DBMS_OUTPUT.PUT_LINE('변경 전 컬럼 값 : ' || :old.dname);
    DBMS_OUTPUT.PUT_LINE('변경 후 컬럼 값 : ' || :new.dname);
END;
/
UPDATE dept SET dname = '총무부' WHERE deptno = 30;   -- 인사과 → 총무부 출력
```
> ⚠️ 슬라이드의 `sum_trigger` 처럼 **행 트리거 안에서 같은 테이블(emp)을 SELECT** 하면, 여러 행에 영향을 주는 문장(예: `INSERT ... SELECT`, 여러 행 UPDATE)에서는 **변경 중인 테이블(mutating table) 오류 ORA-04091** 이 날 수 있다. 한 행짜리 `INSERT ... VALUES` 는 예외적으로 허용되어 예제가 동작한다. 집계가 필요하면 문장 트리거로 만드는 편이 안전하다.

## 4. 종합 예제: 수강신청 시스템
### 테이블
| 테이블 | 키 | 주요 컬럼 |
|---|---|---|
| STUDENT | s_id | s_name, s_addr, s_year, s_college, s_major, **s_pwd** |
| COURSE | (c_id, c_id_no) | c_name, **c_unit**(학점) |
| PROFESSOR | p_id | p_name, ... |
| ENROLL | (s_id, c_id, c_id_no) | e_year, e_semester, e_score |
| TEACH | (p_id, c_id, c_id_no, t_year, t_semester) | **t_time**, t_where, **t_max**(정원) |

### 함수: 날짜 → 수강신청 년도·학기
- 11·12월 → **다음 해 1학기**, 1~4월 → 그 해 1학기, 5~10월 → 그 해 2학기
```sql
CREATE OR REPLACE FUNCTION Date2EnrollYear(dDate IN DATE) RETURN NUMBER IS
    nYear NUMBER; sMonth CHAR(2);
BEGIN
    SELECT TO_NUMBER(TO_CHAR(dDate, 'YYYY')), TO_CHAR(dDate, 'MM') INTO nYear, sMonth FROM DUAL;
    IF (sMonth = '11' OR sMonth = '12') THEN nYear := nYear + 1; END IF;
    RETURN nYear;
END;
/
-- Date2EnrollSemester: 11, 12, 01~04 월 → 1, 나머지 → 2
```

### 프로시저: InsertEnroll(학번 IN, 과목번호 IN, 분반 IN, 결과메시지 OUT)
흐름 = **검사 4가지 → 모두 통과하면 INSERT + COMMIT**, 하나라도 걸리면 **사용자 정의 예외**로 메시지
| 검사 | 방법 | 예외 → 메시지 |
|---|---|---|
| E-1 최대 학점 | 이번 학기 신청 학점 합 + 새 과목 학점 > 18 | too_many_sumCourseUnit → 최대학점을 초과하였습니다 |
| E-2 같은 과목 | ENROLL 에 같은 (학번, 과목) 이 있나 | too_many_courses → 이미 등록된 과목을 신청하였습니다 |
| E-3 정원 | 현재 신청 인원 ≥ TEACH.t_max | too_many_students → 수강신청 인원이 초과되어 등록이 불가능합니다 |
| E-4 시간 중복 | 새 과목 시간 **INTERSECT** 이미 신청한 과목 시간 → 개수 > 0 | duplicate_time → 이미 등록된 과목 중 중복되는 시간이 존재합니다 |
| 그 밖 | `WHEN OTHERS THEN ROLLBACK; result := SQLCODE;` | |

```sql
-- 핵심 구조만
nYear := Date2EnrollYear(SYSDATE);  nSemester := Date2EnrollSemester(SYSDATE);
SELECT SUM(c.c_unit) INTO nSumCourseUnit FROM course c, enroll e WHERE ...;
IF (nSumCourseUnit + nCourseUnit > 18) THEN RAISE too_many_sumCourseUnit; END IF;
...
INSERT INTO enroll(s_id, c_id, c_id_no, e_year, e_semester) VALUES (...);
COMMIT;  result := '수강신청 등록이 완료되었습니다.';
EXCEPTION
    WHEN too_many_sumCourseUnit THEN result := '최대학점을 초과하였습니다.';
    ...
```
> ⚠️ 그 학기에 신청한 과목이 하나도 없으면 `SUM` 이 **NULL** 이고 `NULL + 학점 > 18` 은 참이 아니어서 통과한다(결과적으로 맞음). 의도를 분명히 하려면 `NVL(SUM(c.c_unit), 0)` 을 쓰는 게 안전하다.

### 프로시저: SelectTimeTable(학번, 년도, 학기) — 매개변수 커서
```sql
CURSOR cur (sStudentId VARCHAR2, nYear NUMBER, nSemester NUMBER) IS
    SELECT e.c_id, c.c_name, e.c_id_no, c.c_unit, t.t_time, t.t_where
    FROM enroll e, course c, teach t
    WHERE ... ORDER BY 5;           -- 5번째 컬럼(t_time, 교시) 순
OPEN cur(sStudentId, nYear, nSemester);
LOOP
    FETCH cur INTO sId, sName, nIdNo, nUnit, nTime, sWhere;
    EXIT WHEN cur%NOTFOUND;
    nTotUnit := nTotUnit + nUnit;
END LOOP;
DBMS_OUTPUT.PUT_LINE('총 ' || cur%ROWCOUNT || ' 과목과 총 ' || nTotUnit || '학점');
CLOSE cur;
```
- 테스트 결과: C400(이미 신청), C900(정원 초과), M100(시간 중복), C800(정상), M700(18학점 초과) → 시간표 6과목 18학점

### 트리거: BeforeUpdateStudent — 비밀번호 규칙
- 요구: 비밀번호 **4자리 이상**, **공백 불가** → 제약조건으로 표현하기 번거로운 규칙을 행 트리거로
```sql
CREATE OR REPLACE TRIGGER BeforeUpdateStudent
BEFORE UPDATE ON student FOR EACH ROW
DECLARE
    underflow_length EXCEPTION; invalid_value EXCEPTION; nLength NUMBER; nBlank NUMBER;
BEGIN
    SELECT LENGTH(:new.s_pwd), INSTR(:new.s_pwd, ' ') INTO nLength, nBlank FROM DUAL;
    IF (nLength < 4) THEN RAISE underflow_length;
    ELSIF (nBlank > 0) THEN RAISE invalid_value;
    END IF;
EXCEPTION
    WHEN underflow_length THEN RAISE_APPLICATION_ERROR(-20002, '암호는 4자리 이상이어야 합니다');
    WHEN invalid_value    THEN RAISE_APPLICATION_ERROR(-20003, '암호에 공란은 입력되지 않습니다');
END;
/
```
- `UPDATE student SET s_pwd = '12' ...` → ORA-20002, `'13 45'` → ORA-20003, **수정되지 않음** (BEFORE 트리거에서 오류를 내면 그 DML 이 취소)

## 5. 실습에서 자주 쓰는 도구 (개념)
- 출력 정렬: `RPAD(값, 길이)` 로 칸 맞춤, 줄바꿈 `CHR(10)`
- 실행 기록 제출: SQL*Plus `SPOOL 파일명` ... `SPOOL OFF`
- 문자열 함수: `LENGTH`, `INSTR(문자열, 찾을값)`(위치, 없으면 0), `TO_CHAR(날짜, 'MM')`, `TO_NUMBER`

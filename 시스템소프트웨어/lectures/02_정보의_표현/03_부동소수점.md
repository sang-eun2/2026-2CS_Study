# 03. 부동소수점: IEEE 754, 반올림, 연산 (3. Floating Point + 백업 자료)

> 출처: `2026-2/시스템소프트웨어/3. floating_point.pdf`, `3_부동소수점_백업자료 (1).pdf` (CS:APP 2.4)

## 한눈에 보기
> 지수를 따로 저장해 **소수점을 옮겨 다니게** 하고, 연산 결과는 **정확한 값을 한 번 반올림**한 값(기본: 최근접·짝수)으로 저장한다. 그래서 0.1 은 정확히 못 담고, 결합·분배 법칙이 깨진다.

| 형식 | 부호 | 지수(exp) | 소수(frac) | 바이어스 | 유효 비트 | 상대 오차 상한 |
|---|---|---|---|---|---|---|
| float (binary32) | 1 | 8 | 23 | 127 | 24 | 2⁻²⁴ (십진 약 7자리) |
| double (binary64) | 1 | 11 | 52 | 1023 | 53 | 2⁻⁵³ (약 16자리) |

---

## Part A. 2진 소수
- 소수점 아래 i 번째 비트의 자리값 = **2⁻ⁱ** → 1011.101₂ = 8+2+1 + 1/2 + 1/8 = **11.625**
- 0.11…1₂ (j 개) = **1 − 2⁻ʲ**
- **분모가 2의 거듭제곱인 수만 유한한 2진 소수**. 0.1 = 1/10 은 분모에 5 가 있어 무한 반복(0.0001100110011…₂)
- 10진 → 2진: **2를 곱할 때마다 정수부가 다음 비트** (0.375 → 0, 1, 1 → 0.011₂)
- **고정소수점**은 촘촘함과 범위를 맞바꿈 (8비트: 6+2 → 간격 1/4 최대 63.75 / 2+6 → 간격 1/64 최대 3.98) → 그래서 **지수를 따로** 둔다
- 지수 E 가 1 늘면 값 2배: v = M × 2ᴱ (1.101₂ × 2³ = 13)

## Part B. IEEE 754
**v = (−1)ˢ × M × 2ᴱ**

### 지수 필드 e 로 종류 구분 ⭐
| e (binary32) | frac | 종류 | M | E |
|---|---|---|---|---|
| 1 ~ 254 | 아무거나 | **정규값** | **1.frac** (숨은 1) | **e − 127** (−126 ~ 127) |
| 0 | 0 | ±0 | | |
| 0 | ≠ 0 | **비정규값** | **0.frac** | **1 − 127 = −126** (−127 아님!) |
| 255 | 0 | ±∞ | | |
| 255 | ≠ 0 | NaN | | |

- **숨은 1**: 정규값의 맨 앞은 항상 1 → 저장 안 함 → 23비트로 24비트 정밀도
- **바이어스**: e = E + 127 로 저장 → e 의 순서 = E 의 순서 → 양수는 비트를 정수처럼 비교 가능
- 표기 주의: 교재(CS:APP)는 e = 편향 지수, E = 실제 지수 (IEEE 754 문서는 반대)

### 인코딩 예: 15213.0f
1. 15213 = 11101101101101₂ = **1.1101101101101₂ × 2¹³**
2. exp = 13 + 127 = 140 = **10001100**
3. frac = 1101101101101 뒤에 0 을 10개
4. → **0x466DB400** (유효 비트 14개 ≤ 24 → 정확)

### 비정규값 (점진적 언더플로)
- 최소 정규값 아래를 **같은 간격 Δ = 2^{Emin−n} = 2⁻¹⁴⁹** 로 0 까지 채움. 0 근처에선 지수 대신 **유효 비트가 줄어든다**
- 비정규값 **v = F × 2⁻¹⁴⁹** (F = frac 을 정수로 읽은 값)
- 3.5×10⁻⁴⁰ → F = 3.5×10⁻⁴⁰ / 2⁻¹⁴⁹ = 249768.35… → 249768 → **0x0003CFA8** (복원 시 3.499995×10⁻⁴⁰, 반올림 오차)
- 2⁻¹³⁵: E = −135 < −126 → 가수를 9칸 밀어 0.000000001 × 2⁻¹²⁶ → F = 2¹⁴ → **0x00004000**
  - 1.1011₂ × 2⁻¹³⁵ → **0x00006C00**. 앞에 0 이 8개 생겨 유효 비트는 **15개**로 줄어듦

### 주요 수치 (binary32)
| 값 | 크기 |
|---|---|
| 가장 작은 양수 (비정규) | 2⁻¹⁴⁹ |
| 최소 정규값 | 2⁻¹²⁶ ≈ 1.18×10⁻³⁸ |
| 최대 유한값 | (2 − 2⁻²³) × 2¹²⁷ ≈ 3.4028235×10³⁸ |
| 1 근처 간격 (FLT_EPSILON) | 2⁻²³ ≈ 1.19×10⁻⁷ |

### 간격은 값이 클수록 넓다
- 이웃한 두 값 차이 **Δ = 2^{E−n}**. 지수 구간마다 같은 개수의 눈금이 2배 넓은 구간에 퍼짐
- **2²⁴ = 16,777,216 부터는 간격 2** → 정수 1 도 표현 못 함

### 특수값
- 양의 오버플로, 1.0/+0.0 → **+∞** / 0.0/0.0, ∞−∞, √−1 → **NaN**
- **NaN 은 자기 자신과도 같지 않다**: `==, <, >` 거짓, `!=` 참 → `x != x` 는 x 가 NaN 일 때만 참. 판별은 `isnan()`
- 비트 비교: 0 이상 값은 비트를 unsigned 로 읽어 크기 비교 가능 (음수는 반대, −0 과 +0 은 비트 다르고 값 같음)

### 값 변환 vs 비트 복사
```c
float f = 1.5f;              // 0x3FC00000
unsigned a = (unsigned)f;    // 값 변환 → 1
unsigned u; memcpy(&u, &f, sizeof u);   // 비트 복사 → 0x3FC00000
printf("s=%u exp=%u frac=%06X\n", u >> 31, (u >> 23) & 255u, u & 0x7FFFFFu);
// 15213.0f → 466DB400 s=0 exp=140 frac=6DB400
// 0.1f     → 3DCCCCCD s=0 exp=123 frac=4CCCCD
```
포인터 캐스팅 대신 memcpy → 별칭 규칙 위반 없음

## Part C. 반올림
- IEEE 754 의 약속: **결과 = 정확한 값을 (연산마다) 한 번 반올림한 것**
- 반올림이 일어나는 곳: 저장할 때(`0.1f` = 0.100000001490116…), 곱셈(24×24 = 48비트), 덧셈(지수 맞추며 밀려난 비트)

### 네 가지 방식
| 방식 | 1.4 | 1.5 | 2.5 | −1.5 |
|---|---|---|---|---|
| 0 쪽 버림 | 1 | 1 | 2 | −1 |
| −∞ 쪽 | 1 | 1 | 2 | −2 |
| +∞ 쪽 | 2 | 2 | 3 | −1 |
| **최근접·짝수 (기본)** | 1 | **2** | **2** | −2 |

- 먼저 **거리**로 고르고, **정확히 가운데일 때만 짝수 쪽**(남길 마지막 비트가 0)
- 이웃한 두 표현값은 frac 이 정수로 1 차이 → 끝 비트가 항상 달라 짝수는 늘 하나
- **왜 짝수?** 늘 위로 올리면 오차가 + 로만 쌓임. 짝수 규칙은 올림·내림이 섞여 상쇄 (편향 감소, 오차 0 보장은 아님)
- 실제 사고: 패트리엇 미사일(1991, 0.1초를 24비트 고정소수점에 버림 → 100시간 뒤 0.34초, 약 575m 오차, 28명 사망), 밴쿠버 증권거래소 지수(1982~83, 매번 버림 → 1000 이 22개월 뒤 524.811, 정정값 1098.892)

### 2진 반올림과 G·R·S
- 버릴 부분을 **반 칸**과 비교: 미만 → 버림, 초과 → 올림, 딱 반 → 짝수 쪽
- **L** = 남길 마지막 비트, **G** = 첫 버릴 비트, **R** = 다음 비트, **S(sticky)** = 그 뒤 비트들의 OR
- **올림 조건: G ∧ (R ∨ S ∨ L)**
- 끝의 1 하나도 S 에 남겨야 "정확히 반" 과 "반 초과" 를 구별 (10.10|1000 → 유지, 10.10|1001 → 10.11)

| 입력 (소수 둘째 자리까지) | 버릴 부분 | 결과 |
|---|---|---|
| 10.00011 | 011 < 반 | 10.00 |
| 10.00110 | 110 > 반 | 10.01 |
| 10.11100 | 100 = 반, 끝 1(홀) | 11.00 |
| 10.10100 | 100 = 반, 끝 0(짝) | 10.10 |

### 오차 상한
- 최근접 반올림의 오차 ≤ **Δ/2** (두 거리의 합이 Δ 로 일정하므로 작은 쪽은 절반 이하)
- 상대 오차 ≤ (2^{E−24}) / 2ᴱ = **2⁻²⁴** (단위 반올림 u). double 은 2⁻⁵³

### 2²⁴ + 1 은 왜 2²⁴ 가 되나
- 2²⁴ 이상에선 마지막 유효 자리값이 2 → 더한 1 은 **딱 반 칸** → 끝 비트가 0 인 **2²⁴** 선택
- `(int)(float)16777217` = **16777216**. |n| ≤ 2²⁴ 인 정수는 모두 정확

## Part D. 연산 절차와 깨지는 법칙
공통 4단계: **① 자리 맞춤 → ② 가수 계산(여분 비트 유지) → ③ 정규화 → ④ 반올림 (+ 재정규화·범위 확인)**

### 곱셈
- **부호 = s₁ XOR s₂**, **지수 = E₁ + E₂**, 가수 = M₁ × M₂
- 1 ≤ M₁M₂ < 4 → 정규화는 **많아야 한 칸** (2 이상이면 ÷2, E+1)
- 예(4비트 모형): 1.5 × 1.75 = 10.101₂ = 2.625 → 1.0101₂×2¹ → 반 칸 동점 → 짝수 → **1.010₂×2¹ = 2.5**
- (−1.5)×(+1.75): 0xBFC00000 × 0x3FE00000 = 0xC0280000 (맨 위 비트만 1⊕0)

### 덧셈
- **작은 쪽 가수를 오른쪽으로 밀어** 지수를 맞춤 (M₂·2^{E₂} = M₂·2^{−(E₁−E₂)}·2^{E₁})
- 13 + 2.25: 1.101₂×2³ + 0.01001₂×2³ = 1.11101₂×2³ = 15.25 (binary32 정확, 4비트 모형이면 15)
- 반올림이 다시 정규화를 부를 수 있다: 1.1111₂ → 반 칸 동점 → 10.000₂ → 1.000₂×2¹
- 뺄셈으로 앞자리가 사라지면 왼쪽으로 여러 칸 정규화 (1.0001₂ − 1.0000₂ = 1.0₂×2⁻⁴)
- 부호는 XOR 로 안 끝남 (크기 비교 필요)

### 깨지는 법칙 ⭐
| 법칙 | 반례 (float) | 이유 |
|---|---|---|
| 결합 | `(1 + 2²⁴) − 2²⁴ = 0`, `1 + (2²⁴ − 2²⁴) = 1` | 첫 덧셈의 반올림에서 1 을 잃음 |
| 결합 | 1e10f + 3.14 = 1e10f | 그 근처 간격 1024, 반 칸 512 보다 작음 |
| 분배 | x=y=z=1e20f: x(y−z) = 0, xy − xz = ∞ − ∞ = **NaN** | 곱이 최댓값 초과 |
| 0.1+0.2 | `0.1 + 0.2 != 0.3` (double) | 정확한 합이 이웃 L, U 의 정확히 중간 → 짝수인 U(0.30000000000000004) |

- 비교는 `==` 대신 허용 오차: `fabs(a - b) <= fmax(atol, rtol * fmax(fabs(a), fabs(b)))`

### C 의 형 변환
| 변환 | 결과 |
|---|---|
| int → float | **반올림될 수 있음** (24비트) |
| int → double | 값 보존 (53비트) |
| float → double | 값 보존 |
| double → float | 정밀도 손실·오버플로 가능 |
| 실수 → int | **0 쪽 버림**: `(int)3.9 = 3`, `(int)-3.9 = -3`. 범위 밖·NaN·∞ 는 UB |

- 리터럴: `3.14` 는 double, `3.14f` 는 float

## 확인 문제 풀이
| 문제 | 답 |
|---|---|
| 110.011₂ 를 10진으로, 3/8 을 2진으로 | 6.375 / 0.011₂ |
| exp = 10000010 일 때 E | 130 − 127 = **3** |
| exp 전부 1 인 두 경우 | frac = 0 → ±∞, frac ≠ 0 → NaN |
| $2.50, $3.50 짝수 반올림 | $2, $4 (늘 올림이면 $3, $4) |
| 10.01100 을 소수 두 자리로 | 버릴 100 = 반, 끝 1(홀) → **10.10** |
| 11.375 를 float 로 | 1011.011₂ = 1.011011₂×2³ → s=0, exp=130=10000010, frac=0110110…0 → **0x41360000** |
| x != x 가 참일 때 | x 가 NaN 일 때 |
| (int)−3.9 | −3 (0 쪽 버림) |

# 02. 정수 표현과 연산: unsigned, 2의 보수, 형 변환, 오버플로 (2-2. Bits, Bytes, and Integers Part 2)

> 출처: `2026-2/시스템소프트웨어/2-2. bits_bytes_part2 (1).pdf` (CS:APP 2.2~2.3)

## 한눈에 보기
- unsigned 와 2의 보수의 차이는 **최상위 비트 가중치의 부호 하나뿐** → 음수 영역에서 정확히 2ʷ 차이
- 범위는 비대칭: **|TMin| = TMax + 1**
- 캐스팅(T2U/U2T)은 **비트는 그대로, 해석만** 바꾼다. 식에 unsigned 가 섞이면 조용히 unsigned 비교가 된다 → `-1 < 0U` 는 **거짓**
- 확장은 값 보존(영 확장/부호 확장), 절단은 **mod 2ʷ**
- unsigned 연산은 모듈러, **signed 오버플로는 C 에서 정의되지 않은 동작(UB)**

> 표기: B2U = 비트→unsigned, B2T = 비트→2의 보수, T2U/U2T = 해석 바꾸기, 아래첨자 w = 비트 수

---

## Part A. 같은 비트, 두 가지 읽는 법
### 인코딩 식
| | 식 | [1011] (w=4) |
|---|---|---|
| **unsigned** | B2U(x) = Σ xᵢ·2ⁱ | 8+0+2+1 = **11** |
| **2의 보수** | B2T(x) = **−x_{w−1}·2^{w−1}** + Σ_{i<w−1} xᵢ·2ⁱ | −8+0+2+1 = **−5** |

- 차이 11 − (−5) = 16 = 2⁴. 일반적으로 **u − t = x_{w−1}·2ʷ**
- **T2U(x) = x + 2ʷ (x < 0), x (x ≥ 0)**
- 모든 비트 1 = UMax = 2ʷ − 1 (등비합), 2의 보수로는 **−1**

### 보수와 음수 만들기
- 1의 보수: 비트 반전 / 2의 보수: **반전 후 +1**
- **−x == ~x + 1** (x + ~x = 모든 비트 1 = −1 이므로)
- 15213 = 0x3B6D → 반전 0xC492 → +1 → **0xC493 = −15213** (검산: 0x3B6D + 0xC493 = 0x10000)
- 2의 보수에서 −b 의 비트를 unsigned 로 읽으면 **2ʷ − b** (−3 → 16 − 3 = 13 = 1101)

### 왜 2의 보수인가
| 방식 | 0 의 개수 | 뺄셈 |
|---|---|---|
| 부호-크기 | 2개 (0000, 1000) | 별도 회로 |
| 1의 보수 | 2개 (0000, 1111) | 순환 자리올림 필요 |
| **2의 보수** | **1개** | **덧셈 그대로**: a − b = a + (2ʷ − b) ≡ a − b (mod 2ʷ) |

### 범위 ⭐
| | 비트 | 값 | w=4 | w=8 | w=16 | w=32 |
|---|---|---|---|---|---|---|
| UMax | 11…1 | 2ʷ − 1 | 15 | 255 | 65,535 | 4,294,967,295 |
| TMax | 01…1 | 2^{w−1} − 1 | 7 | 127 | 32,767 | 2,147,483,647 |
| TMin | 10…0 | −2^{w−1} | −8 | −128 | −32,768 | −2,147,483,648 |
| −1 | 11…1 | | | | | |

- 음수가 하나 더 많은 이유: **0 이 최상위 비트 0 쪽(양수 절반)을 한 칸 차지**
- **|TMin| = TMax + 1**, **UMax = 2·TMax + 1**
- 코드에선 `INT_MAX`, `INT_MIN` (`<limits.h>`)

### TMin 의 함정
- −TMin: ~1000 = 0111 → +1 = **1000** (자기 자신). +8 은 4비트로 표현 불가
- C 에서 `-INT_MIN`, `abs(INT_MIN)`, `INT_MIN / -1` 은 모두 **UB** (나눗셈은 x86-64 에서 예외로 종료되기도)
- 안전하게: `if (x == INT_MIN)` 따로 처리, 또는 `llabs((long long)x)`. `-fsanitize=undefined` 로 검출

## Part B. 형 변환, 확장, 절단
### 부호 ↔ 무부호 = 안경만 바꿔 끼기
| 비트 | signed | unsigned |
|---|---|---|
| 0111 | 7 | 7 |
| 1000 | −8 | 8 (+16) |
| 1011 | −5 | 11 (+16) |
| 1111 | −1 | 15 (+16) |

- `int t = -1; unsigned u = t;` → 4,294,967,295 (명시적이든 암묵적이든 같음, 암묵적이 더 위험)
- GCC `-Wsign-conversion`, `-Wsign-compare` 로 경고

### 상수에도 형이 있다 (LP64)
| 상수 | 형 |
|---|---|
| 0 / 0U | int / unsigned int |
| 2147483647 | int |
| 2147483648 | **long** (10진은 int → long → long long) |
| 0x7FFFFFFF / 0x80000000 | int / **unsigned int** (8·16진은 unsigned 도 후보) |

- `-2147483648` 은 int 가 아니라 long 에 부호를 붙인 것 → 그래서 `INT_MIN` 은 `(-2147483647 - 1)` 로 정의

### 공통 자료형 정하는 순서: 정수 승격 → 순위 → 표현 범위
- 순위: short < int < long < long long (**크기가 아니라 C 표준이 정한 순위**. LP64 에서 long 과 long long 은 둘 다 64비트지만 순위는 long 이 낮다)
- 부호가 다른 S(signed) 와 U(unsigned) 가 만나면
  1. U 의 순위 ≥ S 의 순위 → **U 로**
  2. 아니고, S 가 U 의 **모든 값**을 담을 수 있으면 → **S 로**
  3. 둘 다 아니면 → S 에 대응하는 unsigned 형으로

| 식 (LP64) | 공통 형 |
|---|---|
| int + unsigned int | unsigned int |
| long long + unsigned int | **long long** → `-1LL < 0U` 는 참 |
| long long + unsigned long | unsigned long long |

### 함정 표 (32비트 int)
| 식 | 결과 | 이유 |
|---|---|---|
| `-1 < 0U` | **0** | −1 → 4,294,967,295 |
| `2147483647U > -2147483647-1` | **0** | TMin → 2,147,483,648 |
| `2147483647 > (int)2147483648U` | 1 | 캐스팅 결과가 TMin |
| `(unsigned)-1 > -2` | 1 | 둘 다 커지지만 순서 유지 |

> 0 ~ TMax 는 순서 그대로, **TMin ~ −1 구간만 통째로 가장 큰 양수 쪽으로** 이동

### 실제 버그
```c
if (strlen(s) - strlen(t) > 0)   // size_t 라서 2 - 3 = 18446744073709551615 → 항상 참

unsigned i;
for (i = n-1; i >= 0; i--) ...   // i >= 0 은 항상 참 + 0 에서 빼면 2³²−1 → 무한 루프
// 고침: int i 를 쓰거나, for (i = n; i > 0; i--) a[i-1]

int copy(char *dst, char *src, int len) {
    if (len > MAX) return -1;    // len = -1 이 통과!
    memcpy(dst, src, len);       // size_t 로 변환되어 거대한 크기 → 버퍼 오버플로
}
// 고침: if (len < 0 || len > MAX), 또는 처음부터 size_t 로 받기
```
- `10U + (-5)` 는 우연히 5 지만 `3U + (-5)` = 4294967294 → 테스트를 통과해 버리는 버그

### 확장 (작은 형 → 큰 형): 값 보존
- **영 확장**(unsigned): 앞을 0 으로
- **부호 확장**(2의 보수): 앞을 **최상위 비트 복사**로
- 왜 보존? 새 부호 자리 −2ʷ + 기존 자리 2^{w−1} = −2^{w−1} (예: 1101 → 11101, −16 + 8 = −8)
- 같은 1101: unsigned 13 → 0000 1101, signed −3 → 1111 1101

### 절단 (큰 형 → 작은 형): mod 2ʷ
- x = q·2ʷ + r → 남는 값 **r = x mod 2ʷ**, signed 로 읽으면 r ≥ 2^{w−1} 일 때 r − 2ʷ
- int 53191 → short: 0xCFC7 → 53191 − 65536 = **−12345**
- int 1000 → short: 1000 (범위 안이면 보존)
- 범위 밖 signed 변환은 C11 에서 **구현 정의** (GCC 는 위처럼 mod)

## Part C. 유한한 비트 안의 계산
### unsigned 덧셈
- **UAdd(u, v) = (u + v) mod 2ʷ** (맨 위 올림 버림)
- 9 + 12 = 21 → **5** (w=4)
- **오버플로 검사: `s = u + v; if (s < u)`** (넘치면 s = u + v − 2ʷ < u)

### 2의 보수 덧셈
- **비트 연산은 UAdd 와 완전히 같다.** 읽는 법만 다름
- 참값 > TMax → 2ʷ 빼기 (양의 오버플로), 참값 < TMin → 2ʷ 더하기 (음의 오버플로)
  - 5 + 6 = −5, −8 + −5 = 3 (w=4)
- **같은 부호끼리 더해 부호가 바뀌면 오버플로. 부호가 다르면 절대 안 넘침**
- ⚠️ C 에선 UB → 컴파일러가 `if (x + 1 < x)` 같은 사후 검사를 **삭제할 수 있음**

### 올림(carry) ≠ 오버플로(overflow)
| 식 (w=4) | 올림 | unsigned | signed |
|---|---|---|---|
| 1111 + 0001 | 있음 (CF=1) | **넘침** (15+1) | 정상 (−1+1=0) |
| 0111 + 0001 | 없음 | 정상 (7+1=8) | **넘침** (OF=1, 7+1=−8) |

- 하드웨어: 전가산기 w 개를 이은 덧셈기 하나. **CF = 최상위 올림 c_w**, **OF = c_w ⊕ c_{w−1}**
- 뺄셈 a − b = a + ~b + 1 → b 반전 + c₀ = 1. 뺄셈기가 따로 없다
- 무부호 비교 `ja`/`jb` 는 CF, 부호 있는 비교 `jg`/`jl` 은 OF 를 본다

### 곱셈
- w 비트 곱은 최대 2w 비트 필요 → **상위 절반이 사라짐**
- **UMult(u, v) = (u·v) mod 2ʷ**. signed 와 unsigned 곱의 **하위 w 비트는 같다** (u = x + aM 이면 uv − xy 가 M 의 배수)
  - 1101×1100: unsigned 13×12 = 156 → 1100, signed −3×−4 = 12 → 1100
- **계산 시점의 형이 결과를 정한다**
```c
long long r1 = 50000 * 50000;        // int 곱셈에서 이미 UB
long long r2 = 1LL * 50000 * 50000;  // 2500000000
```
  - 어셈블리: r1 방식 = `imull`(32비트 곱) 후 `movslq`(부호 확장) → −1,794,967,296 / r2 방식 = 먼저 `movslq` 후 `imulq`(64비트 곱)
- `malloc(n * sizeof(elem))` 은 곱이 넘칠 수 있음 → `calloc(n, size)` 는 검사해 줌
- 더 큰 정수: GMP (`mpz_t`, 워드 여러 개를 이어 붙임, RSA 등)

### 시프트로 곱하기
- `x << k` = x × 2ᵏ (mod 2ʷ). 24x = (x << 4) + (x << 3)
- 조건: 0 ≤ k < w, signed 는 x ≥ 0 이고 결과가 범위 안일 때만 정의
- 소스엔 `x * 24` 로 쓰고 최적화는 컴파일러에게

### 산술 오른쪽 시프트 = 내림(floor)
- `x >> k` = **⌊x / 2ᵏ⌋**, C 의 `/` 는 **0 쪽 버림** → 음수에서 1 차이
  - `-15 >> 2 = -4`, `-15 / 4 = -3`
- **음수 나눗셈 보정: `x / 2ᵏ == (x + (2ᵏ − 1)) >> k`** (x < 0)
  - (−15 + 3) >> 2 = −3 ✅, (−16 + 3) >> 2 = −4 ✅ (나누어떨어지면 경계를 넘지 않음)
  - 더할 값은 정확히 d − 1 뿐 (b = 2 면 −15 틀림, b = 4 면 −16 틀림)
- 컴파일러는 `x / 2` 를 분기 없이: `shrl $31` 로 부호 비트를 보정값으로 → `addl` → `sarl`

### 실무 안전 수칙
```c
int mid = lo + (hi - lo) / 2;            // (lo + hi) / 2 는 넘칠 수 있음
if (__builtin_add_overflow(a, b, &r))    // 권장
if (b > 0 && a > INT_MAX - b) ...        // 직접 검사는 부호를 나눠서
if (b < 0 && a < INT_MIN - b) ...
```

| 문제 | 답 |
|---|---|
| w=5, [10110] | unsigned 22, 2의 보수 −16+6 = **−10** |
| w=8 TMin/TMax/UMax | −128 (1000 0000) / 127 (0111 1111) / 255 (1111 1111) |
| −x == ~x + 1 이 안 되는 값 | **TMin** (−TMin 이 표현 불가) |
| (unsigned)(-1) | 4,294,967,295 = −1 + 2³² |
| 40000 → 16비트 short | 40000 − 65536 = **−25536** |
| w=4, 9 + 12 (unsigned) | 21 mod 16 = **5** |
| 1111+0001 vs 0111+0001 | 2의 보수 오버플로는 **0111+0001** (양수+양수=음수) |

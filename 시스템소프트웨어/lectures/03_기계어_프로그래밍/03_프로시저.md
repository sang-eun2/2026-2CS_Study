# 03. 프로시저: 호출 규약, 스택 프레임, 재귀 (6-1. Procedures)

> 출처: `2026-2/시스템소프트웨어/6-1. procedures (1).pdf` (CS:APP 3.7)

## 한눈에 보기
> 함수 호출 = **제어 이동 + 데이터 전달 + 메모리 할당**을 함께 다루는 약속(ABI). 복귀 주소는 스택에, 정수 인자 6개는 정해진 레지스터에 실리고, 프레임이 쌓였다 풀리는 구조(LIFO) 덕분에 **재귀가 저절로** 동작한다.

| 필요한 것 | x86-64 (리눅스 System V) |
|---|---|
| 제어 이동 | `call`/`ret`, 스택에 복귀 주소 |
| 인자 전달 | 레지스터 6개, 넘으면 스택 |
| 반환값 | `%rax` (int 면 `%eax`) |
| 지역 변수 | 레지스터, 모자라면 스택 |

---

## Part A. 제어 이동과 호출 규약
### call / ret
- `call Label`: ① **다음 명령 주소를 push** ② Label 로 점프
- `ret`: ① 스택에서 주소 pop ② 그 주소로 점프
- 예: `0x400563: callq 0x400540 <multstore>` → %rsp 가 8 줄고 그 칸에 0x400568
- **짝이 맞아야** 한다. 복귀 주소가 덮이면 엉뚱한 곳으로 → 11주차 버퍼 오버플로 공격
- `%rip` 는 mov 피연산자로 못 씀. call·ret·jmp 가 바꿈 (GDB 에선 `$pc`)

### 인자 레지스터 ⭐
| 순서 | 64비트 | 32 | 16 | 8 |
|---|---|---|---|---|
| 1 | %rdi | %edi | %di | %dil |
| 2 | %rsi | %esi | %si | %sil |
| 3 | %rdx | %edx | %dx | %dl |
| 4 | %rcx | %ecx | %cx | %cl |
| 5 | %r8 | %r8d | | |
| 6 | %r9 | %r9d | | |

- **7번째 이후**: 호출자가 call 전에 스택에 놓음. 진입 직후 `(%rsp)` = 복귀 주소, `8(%rsp)` = 7번째, `16(%rsp)` = 8번째
- 부동소수점 인자: `%xmm0~%xmm7`, 반환 `%xmm0` (정수 인자와 따로 셈)
- 이 약속 = **ABI** → 다른 사람이 컴파일한 라이브러리와도 함께 동작

### 값 전달: 포인터도 복사된다
```c
void move(int *p) { p = p + 1; }   // 복사본만 바뀜 → 어셈블리: ret 하나
void set(int *p)  { *p = 7; }      // 메모리가 바뀜 → movl $7, (%rdi)
```
swap 이 주소를 받는 이유: 값을 받으면 복사본만 바뀐다

### 레지스터 보존 규칙 (전체 목록)
| 분류 | 레지스터 | 규칙 |
|---|---|---|
| **호출자 저장 (caller-saved)** | %rax %rcx %rdx %rsi %rdi %r8~%r11 | 호출 뒤에도 필요하면 **부르는 쪽**이 보관 |
| **피호출자 저장 (callee-saved)** | **%rbx %rbp %r12~%r15** | **불린 쪽**이 바꾸면 반환 전에 복원 |
| 특수 | %rsp | 스택 포인터 |

```asm
# long myfunc(long x) { long t = other(10); return t + x; }
myfunc:
    pushq %rbx          # 빌려 쓸 %rbx 먼저 보관
    movq  %rdi, %rbx    # x 를 안전한 곳으로 (call 이 %rdi 를 덮으니까)
    call  other         # %rdi = 10 으로 호출
    addq  %rbx, %rax
    popq  %rbx          # 반드시 복원
    ret
```

## Part B. 스택 프레임과 재귀
### 스택 프레임 = 함수 한 번의 실행이 쓰는 스택 영역
```
높은 주소  [호출한 함수의 프레임 (7번째~ 인자)]
           [복귀 주소]          ← call
           [저장한 레지스터 %rbx] ← push %rbx
           [지역 변수]          ← subq $N, %rsp
낮은 주소                        ← %rsp
```
- 없앨 땐 **만든 순서의 역순**: `addq $N, %rsp` → `pop %rbx` → `ret`
- ret 직전 %rsp 는 복귀 주소를 가리켜야 함
- 보관할 게 없으면 프레임을 안 만들기도 함 (`leaq 1(%rdi), %rax; ret`)
- %rbp 기준점은 선택: `subq $24,%rsp; movq %rdi,8(%rsp)` (%rsp 기준) vs `pushq %rbp; movq %rsp,%rbp; subq $16,%rsp; movq %rdi,-8(%rbp)` (%rbp 기준)

### 지역 변수가 스택에 놓여야 하는 경우: 주소가 필요할 때
```c
long incr(long *p, long val) { long x = *p; *p = x + val; return x; }
long call_incr(void) { long v1 = 15213; long v2 = incr(&v1, 3000); return v1 + v2; }
```
```asm
call_incr:
    subq  $24, %rsp          # 프레임 확보
    movq  $15213, 8(%rsp)    # v1
    leaq  8(%rsp), %rdi      # &v1
    movl  $3000, %esi
    call  incr               # %rax = v2 = 15213, v1 은 18213 으로
    addq  8(%rsp), %rax      # 18213 + 15213 = 33426
    addq  $24, %rsp
    ret
```
- **왜 24바이트? 스택 정렬**: System V 는 **call 직전 %rsp 를 16의 배수**로. 진입 직후엔 복귀 주소 때문에 나머지 8 → 16 확보면 여전히 8(불가), **24 확보면 0**(가능)

### 함수가 끝나면 지역 변수도 끝
```c
int *bad(void) { int v = 42; return &v; }   // 정의되지 않은 동작 (gcc -Wreturn-local-addr 경고)
```
- 반환 후 %rsp 아래는 다음 호출이 덮어씀. 값을 반환하거나, 호출자가 공간을 마련해 주소를 넘길 것

| 종류 | 놓이는 곳 | 수명 |
|---|---|---|
| 일반 지역 변수 | 레지스터 또는 스택 프레임 | 블록 실행이 끝날 때까지 |
| 지역 `static` | 데이터 영역 | 프로그램 끝까지 (`next()` 가 1, 2, 3…) |
| `malloc` 공간 | 힙 | `free` 할 때까지 (free 후 접근은 UB) |

### 재귀: pcount_r (비트 1 개수)
```c
long pcount_r(unsigned long x) {
    if (x == 0) return 0;
    return (x & 1) + pcount_r(x >> 1);
}
```
| x | x&1 (남겨 둘 값) | 다음 호출 | 반환 |
|---|---|---|---|
| 11 (1011) | 1 | pcount_r(5) | 3 |
| 5 (101) | 1 | pcount_r(2) | 2 |
| 2 (10) | 0 | pcount_r(1) | 1 |
| 1 | 1 | pcount_r(0) | 1 |
| 0 | - | 없음 | 0 |

```asm
pcount_r:
    testq %rdi, %rdi
    jne   .L8
    movl  $0, %eax          # x == 0 → 0
    ret
.L8:
    pushq %rbx              # 호출한 쪽의 %rbx 보관
    movq  %rdi, %rbx
    andl  $1, %ebx          # 남겨 둘 값 x&1 → %rbx
    shrq  %rdi              # x >> 1
    call  pcount_r          # 결과 → %rax
    addq  %rbx, %rax        # x&1 + 결과
    popq  %rbx              # 복원
    ret
```
- **같은 %rbx 를 쓰는데 안 섞이는 이유**: 다음 호출이 이전 %rbx 를 스택에 저장하고 반환 전 복원 (callee-saved 규칙). 재귀용 특별 명령은 없다
- pcount_r(0) 진입 직후 스택: 복귀 주소와 저장된 %rbx(main 값, 1, 1, 0)가 번갈아 쌓임 (x≠0 호출은 16바이트씩)
- 너무 깊으면 **스택 오버플로** (리눅스 기본 스택 보통 8MB)

### GDB 로 확인
```
(gdb) break *pcount_r if $rdi == 0   # x=0 진입 직후
(gdb) bt                              # pcount_r 5겹 + main
(gdb) x/9xg $rsp                      # 복귀 주소 5개 + 저장한 %rbx 4개
(gdb) finish                          # 0 → 1 → 1 → 2 → 3
```

## 확인 문제 풀이
| 문제 | 답 |
|---|---|
| call 이 하는 두 가지 | ① 다음 명령 주소 push ② 목적지로 점프 |
| 인자 8개 함수의 7·8번째 | 스택: 진입 직후 8(%rsp), 16(%rsp) |
| caller/callee-saved 예 | %rdx(호출자), %rbx(피호출자) |
| 스택 프레임에 보관하는 값 | 저장한 callee-saved 레지스터(복원 위해), 주소가 필요한 지역 변수 |
| `leaq 8(%rsp), %rdi` 를 C 로 | 첫 인자 = `&v1` (스택 지역 변수의 주소) |
| pcount_r(11) 이 x&1 을 다시 쓸 수 있는 이유 | 하위 호출이 %rbx 를 스택에 저장했다 복원하므로 |
| ABI 가 없다면 | 다른 컴파일러로 만든 라이브러리와 인자·반환 위치가 달라 호출이 깨짐 |

# 01. 기계어 수준 프로그래밍 I: 레지스터, 데이터 이동, 산술, objdump·GDB (4. Machine-Level Programming I)

> 출처: `2026-2/시스템소프트웨어/4. machine_basics (2).pdf` (CS:APP 3.1~3.5, 3.10.2)

## 한눈에 보기
> 어셈블리 = 기계어에 사람이 읽을 이름을 붙인 것. **자료형도 변수 이름도 없다.** 남는 건 폭이 정해진 값과 주소, 그리고 그걸 옮기고 계산하는 명령뿐.

### 어셈블리 한 줄 읽는 순서
1. **무슨 명령?** 이름 + 접미사 `b w l q` 로 연산과 폭
2. **피연산자는 어디?** `$` 즉시값, `%` 레지스터, 괄호 = 메모리 (lea 는 예외)
3. **어느 쪽이 바뀌나?** AT&T 는 **원본 먼저, 목적지 나중**. `op S, D` 는 D ← D op S
4. **C 의 무엇?** `%rdi %rsi %rdx` = 인자, `%rax` = 반환값, 괄호 = `*p`, `a[i]`, `p->f`

## Part A. 왜 어셈블리를 읽나
- C 가 숨기는 것: 값이 레지스터/메모리 중 어디 있나, 변수 주소, 분기 명령, 인자 전달 위치
- **ISA** = 명령의 **의미**에 대한 약속 (명령 종류·형식, 레지스터, 메모리 모델) / **마이크로아키텍처** = **어떻게** 구현하나 (캐시, 파이프라인, 코어 수). Intel 과 AMD 는 내부가 달라도 같은 결과
- x86 계보: 8086(16비트) → IA-32(32비트) → **x86-64**(AMD64/Intel 64, IA-32 하위 호환). **IA-64(Itanium)는 별개 ISA**
- **CISC(x86-64)**: 명령 수 적고 길이 1~15바이트 가변 (`rep movsb` 한 명령으로 복사) / **RISC(ARM)**: 길이 고정, 해독 쉬움 (같은 일에 4명령)

## Part B. C 에서 기계어까지
```
sum.c --gcc -E--> sum.i --gcc -S--> sum.s --gcc -c--> sum.o --링크--> sum
 (텍스트)          (텍스트)          (텍스트)          (바이너리)       (바이너리)
```
- 어셈블러: 텍스트 → 명령 바이트 (주소 미정) / 링커: 오브젝트 + 라이브러리 합치고 주소 결정
- `-Og` 가 읽기 좋다 (`-O0` 장황, `-O2` 원래 코드와 대응 사라짐). `.globl` 같은 `.` 줄은 지시어
- `-fcf-protection=none` 을 빼면 함수 앞에 `endbr64`(4바이트)가 붙음

### 어셈블리가 보는 프로세서 상태 (네 가지뿐)
| 상태 | 내용 |
|---|---|
| **PC** (`%rip`) | 다음 명령 주소 |
| **정수 레지스터 16개** | 각 64비트 |
| **조건 코드** (`%rflags` 안 비트) | 산술·논리 명령이 세우고 분기가 읽음 (mov 는 안 바꿈) |
| **메모리** | 바이트 배열 (코드·데이터·스택) |
부동소수점은 `%xmm0` 등 벡터 레지스터 (이 수업 범위 밖)

### 레지스터: 한 레지스터를 네 가지 폭으로
`%rax`(64) ⊃ `%eax`(32) ⊃ `%ax`(16) ⊃ `%al`(8) — 좁은 이름은 **오른쪽 끝 일부**
- 16개: rax rbx rcx rdx rsi rdi rbp rsp + r8~r15 (r8d / r8w / r8b)
- **인자: %rdi, %rsi, %rdx 순 / 반환값: %rax** / `%rsp` = 스택 꼭대기

### 접미사
| C | 인텔 용어 | 접미사 | 바이트 |
|---|---|---|---|
| char | byte | b | 1 |
| short | word | w | 2 |
| int | double word | l | 4 |
| long, 포인터 | quad word | q | 8 |
- word 가 2바이트인 이유: 8086 이 16비트 기계라서. **접미사 l = long word(4바이트)** 로 C 의 long(8바이트)과 다름
- int x → `movl`/`%eax`, long x → `movq`/`%rax`. 자료형은 **접미사와 레지스터 폭**으로만 남는다

### AT&T vs Intel 표기
| | AT&T (gcc, objdump, 교재) | Intel (인텔 매뉴얼, NASM) |
|---|---|---|
| 순서 | **원본, 목적지** | 목적지, 원본 |
| 레지스터/상수 | `%rbx`, `$0x10` | `rbx`, `0x10` |
| 폭 | 접미사 `movq` | `qword ptr` |
| 메모리 | `8(%rbx,%rcx,4)` | `[rbx + 4*rcx + 8]` |
`movq %rdx, %rbx` ≡ `mov rbx, rdx` (같은 바이트 48 89 d3)

## Part C. 데이터 옮기기
### 피연산자와 주소 일반형 ⭐
**`D(Rb, Ri, S)` → 주소 = D + R[Rb] + R[Ri] × S** (S ∈ {1, 2, 4, 8} = char/short/int/long 크기)

| 피연산자 | 값 |
|---|---|
| `$0x108` | 0x108 그 자체 (상수) |
| `%rax` | R[rax] |
| `0x108` | M[0x108] |
| `(%rax)` | M[R[rax]] (`*p`) |

예: %rax=0x200, %rcx=0x8, %rdx=0x3, M[0x200..0x218] = 0x11, 0x22, 0x33, 0x44
| 피연산자 | 주소 | 값 |
|---|---|---|
| `(%rax)` | 0x200 | 0x11 |
| `8(%rax)` | 0x208 | 0x22 |
| `16(%rax,%rcx)` | 0x218 | 0x44 |
| `(%rax,%rdx,8)` | 0x218 | 0x44 (long a[3]) |
| `0x1F8(,%rdx,8)` | 0x210 | 0x33 |

- `a[i]` ≡ `*(a+i)` → 둘 다 `movq (%rdi,%rsi,8), %rax`. int 배열이면 `movl (%rdi,%rsi,4), %eax`
- 괄호는 **어디서부터**, 접미사는 **얼마나** 읽을지 정함

### mov 의 다섯 조합
| 원본 → 목적지 | 예 | C |
|---|---|---|
| 즉시값 → 레지스터 | `movq $0x4, %rax` | a = 4 |
| 즉시값 → 메모리 | `movq $-147, (%rax)` | *p = -147 |
| 레지스터 → 레지스터 | `movq %rax, %rdx` | b = a |
| 레지스터 → 메모리 | `movq %rax, (%rdx)` | *p = a |
| 메모리 → 레지스터 | `movq (%rax), %rdx` | b = *p |
- **메모리 → 메모리는 불가** → `*q = *p` 는 두 명령. 즉시값은 목적지 불가

### mov 폭과 상위 바이트 (시작 %rax = 0x0011223344556677)
| 명령 | 결과 |
|---|---|
| `movb $-1, %al` | 00 11 22 33 44 55 66 **FF** (나머지 그대로) |
| `movw $-1, %ax` | 00 11 22 33 44 55 **FF FF** |
| `movl $-1, %eax` | **00 00 00 00** FF FF FF FF ← **32비트 쓰기는 상위 4바이트를 0 으로** |
| `movq $-1, %rax` | FF × 8 |
- 레지스터 목적지의 64비트 큰 상수는 `movabsq`(10바이트). 메모리 목적지 즉시값은 32비트까지(부호 확장)

### 확장 이동 movz / movs
- **movz**: 0 으로 채움(영 확장), **movs**: 부호 비트로(부호 확장). 이름 = mov + z/s + 원본 폭 + 목적지 폭
| C | 명령 |
|---|---|
| char → long | `movsbq` |
| unsigned char → long | `movzbq` |
| short → int | `movswl` |
| int → long | `movslq` (짧은 형 `cltq`) |
| unsigned → long | `movl` (**movzlq 는 없다**, movl 이 상위를 0 으로) |
- 좁히기와 int↔unsigned 는 **명령 없음** (낮은 바이트만 쓰거나 그대로 복사)
- 명령 고르는 순서: **C 가 요구하는 값부터** — `signed char -1 → unsigned int` 는 2³²−1 = FFFFFFFF 이어야 하므로 `movsbl` (movzbl 이면 255 로 틀림)

### swap
```asm
swap:                       # xp → %rdi, yp → %rsi
    movq (%rdi), %rax       # t0 = *xp
    movq (%rsi), %rdx       # t1 = *yp
    movq %rdx, (%rdi)       # *xp = t1
    movq %rax, (%rsi)       # *yp = t0
    ret
```

### pushq / popq
- `pushq %rbx` ≈ `subq $8,%rsp` + `movq %rbx,(%rsp)` / `popq %rbx` ≈ `movq (%rsp),%rbx` + `addq $8,%rsp` (push/pop 은 조건 코드를 안 바꿈)
- 스택은 **낮은 주소 쪽으로** 자람. pop 해도 값은 지워지지 않음

### sumstore 한 줄씩
```c
void sumstore(long x, long y, long *dest) { long t = plus(x, y); *dest = t; }
```
| 명령 | 뜻 |
|---|---|
| `pushq %rbx` | %rbx 원래 값을 스택에 맡김 (호출 후에도 보존해야 하는 레지스터) |
| `movq %rdx, %rbx` | dest 를 보존 레지스터로 (call 이 %rdx 를 덮어쓸 수 있어서) |
| `call plus` | 인자는 이미 %rdi, %rsi → 결과 %rax |
| `movq %rax, (%rbx)` | *dest = t |
| `popq %rbx` | %rbx 복원 |
| `ret` | 복귀 |
C 두 줄 → 명령 6개, 14바이트 (1·3·5바이트 가변 길이)

## Part D. 계산하기
### leaq: 주소 계산만, 메모리는 안 읽음
| 명령 | 결과 |
|---|---|
| `movq (%rax,%rdx,8), %rcx` | %rcx = M[0x218] (값) |
| `leaq (%rax,%rdx,8), %rcx` | %rcx = 0x218 (주소, `&a[i]`) |
| `leaq (%rdi,%rsi,4), %rax` | x + 4y |
| `leaq 7(%rdi,%rdi,2), %rax` | **3x + 7** |
- 덧셈+작은 곱셈을 한 명령으로, 결과를 다른 레지스터에, **조건 코드 안 바꿈**

### 산술·논리 명령 (D ← D op S)
| 이항 | C | 단항 | C |
|---|---|---|---|
| `addq S,D` | += | `incq D` | ++ |
| `subq S,D` | **D − S** (-=) | `decq D` | -- |
| `imulq S,D` | *= (D 는 레지스터만) | `negq D` | −x |
| `andq / orq / xorq` | &= \|= ^= | `notq D` | ~x |
- `subq %rax, %rdx` = `rdx -= rax`
- **덧셈·뺄셈·하위 곱셈은 signed/unsigned 같은 명령**. 갈리는 곳: 오른쪽 시프트, 나눗셈, 128비트 전체 곱, 확장, 비교 해석
- `xorl %eax, %eax` = 0 넣기 (2바이트, `movl $0` 은 5바이트, `movq $0` 은 7바이트)
- `andl $0xff, %eax` = 낮은 1바이트만, `orq $0x20` = 비트 5 켜기('A' → 'a')

### test: AND 해서 조건 코드만
- `testq %rax, %rax` → x & x = x 라 ZF(0 인가), SF(음수인가)만 의미. CF·OF 는 항상 0. 피연산자는 안 바뀜
- 조건 코드: **ZF**(0), **SF**(음수), **OF**(signed 넘침), **CF**(unsigned 올림) → 자세히는 5장

### 시프트
| 명령 | 뜻 | C |
|---|---|---|
| `salq k,D` = `shlq` | 왼쪽 (같은 기계어) | << |
| `sarq k,D` | 산술 오른쪽 (부호 비트로) | >> (signed) |
| `shrq k,D` | 논리 오른쪽 (0 으로) | >> (unsigned) |
- k 는 즉시값 또는 **%cl** 만. CPU 는 %cl 의 하위 6비트(q) / 5비트(b·w·l) 만 읽음 (65 → 1칸). C 에선 폭 이상 시프트는 UB
- %rax = −16: sarq $2 → −4, shrq $2 → 0x3FFFFFFFFFFFFFFC (큰 양수)

### ⚠️ sarq 는 나눗셈이 아니다
- −17 >> 2 = **−5**, C 의 −17/4 = **−4** → 컴파일러가 보정:
```asm
leaq 3(%rdi), %rax     # x + 3 준비
testq %rdi, %rdi
cmovns %rdi, %rax      # x >= 0 이면 원래 x
sarq $2, %rax
```

### arith 예 (`-Og`)
```c
long arith(long x, long y, long z) {
    long t1 = x ^ y; long t2 = z * 48; long t3 = t1 & 0x0F0F0F0F; return t2 - t3;
}
```
```asm
xorq %rsi, %rdi            # t1
leaq (%rdx,%rdx,2), %rax   # 3z
salq $4, %rax              # 48z
andl $252645135, %edi      # t3 (andl 이 andq 보다 1바이트 짧고 결과 같음)
subq %rdi, %rax
```
arith(1, 2, 3) = 144 − 3 = 141. 최적화는 C 줄 순서를 지키지 않고 더 싼 명령으로 바꾼다

### 특수 산술: 128비트 곱과 나눗셈
- `imulq S` / `mulq S`: **%rax × S → %rdx:%rax** (상위 : 하위). 하위 64비트는 signed/unsigned 같음
  - 2⁶³ × 2: mulq → %rdx=1, %rax=0 / imulq → %rdx=FF…F, %rax=0
- `idivq S` / `divq S`: 피제수 **%rdx:%rax** ÷ S → 몫 **%rax**, 나머지 **%rdx**
- 나누기 전 준비: signed 는 **`cqto`**(%rax 를 %rdx:%rax 로 부호 확장), unsigned 는 `movl $0, %edx`
  - −17 / 5 → 몫 −3, 나머지 −2 (0 쪽 버림, 나머지 부호는 피제수 따라감)
  - ⚠️ cqto 를 빼먹으면 피제수가 2⁶⁴ − 17 이 되어 **조용히 틀린 답** (y=4 → 4611686018427387899). 몫이 넘칠 때만 SIGFPE

## Part E. objdump 와 GDB
### 오브젝트 파일
- .o = 명령 바이트 + 심볼 테이블 + **재배치 정보**. 주소 미정이라 실행 불가
- `call plus` 가 `e8 00 00 00 00` 인 이유: 링커가 채울 자리 (`R_X86_64_PLT32 plus-0x4`)
- **call 상대 거리 = 목적지 − 다음 명령 주소**: plus(0x1156) − 0x1164 = −0xe → `f2 ff ff ff` (리틀 엔디안 2의 보수)

### 같은 함수, 세 가지 주소
① .o 안 섹션 오프셋 → ② 링크 후 배치 주소(objdump, 예 0x115b) → ③ 실행 중 주소(PIE: 기준주소 0x555555554000 + 0x115b). `-no-pie` 면 ②=③. GDB 는 ASLR 을 꺼서 매번 같음

### 정적 vs 동적 분석
| | 도구 | 보이는 것 | 안 보이는 것 |
|---|---|---|---|
| 정적 | objdump, readelf, nm | 명령 바이트, 심볼, 섹션, 재배치 | 실행 중 값, 실제 분기 |
| 동적 | GDB | 레지스터·메모리 실제 값, 호출 흐름 | 안 지나간 코드 |
(정적/동적 **링크**와는 다른 말)

### objdump
- 출력 = 오프셋 | 바이트 | 어셈블리. **명령 경계에서 시작해야** 함 (한 바이트 어긋나면 다른 명령)
- `-d` 역어셈블, `-S` 소스와 섞어(`gcc -g` 필요), `-t` 심볼, `-r` 재배치, `-h` 섹션, `-M intel`

### GDB
| 실행 | 보기 |
|---|---|
| `break swap`, `break *0x401136` | `disassemble`, `info registers` |
| `run`, `continue` | `p $rax`, `p/x $rax` |
| `stepi`(si, 기계어 1개), `nexti`(ni) | `x/2xg $rsp` (16진 8바이트 2개) |
| `finish` | `x/4dw &arr` (10진 4바이트 4개), `x/i $pc` |
- x 형식: x 16진, d 10진, u 부호없음, s 문자열, i 명령 / 크기: **b 1, h 2, w 4, g 8** (어셈블리 접미사와 다름!)
- 실습 순서: **확인(x/i $pc) → 예측 → 실행(si) → 관찰**
- `break *swap` 은 첫 명령에서, `break swap` 은 프롤로그를 건너뛸 수 있음 (-O0 에서 차이)

### 최적화 수준
- `long add(long x, long y) { long t = x + y; return t; }` → `-O0`: 스택에 저장·재로드 11줄 / `-Og`·`-O2`: `leaq (%rdi,%rsi), %rax` + `ret`

### 이름의 뜻
lea = Load Effective Address, cqto = convert quad to octo, cltq = convert long to quad, e = Extended(32), r = 64비트, a = accumulator, c = counter, si/di = source/destination index, sp = stack pointer, ip = instruction pointer, ABI = Application Binary Interface, ELF = Executable and Linkable Format

## 확인 문제 풀이
| 문제 | 답 |
|---|---|
| long f(a, b, c) 의 c / 반환값 | %rdx / %rax |
| movw, movq 바이트 | 2, 8 |
| %rax=0x100, %rcx=3 일 때 0x10(%rax,%rcx,8) | 0x100 + 0x10 + 0x18 = **0x128** |
| movl $-1,%eax / movw $-1,%ax (시작 0x0011223344556677) | 0x00000000FFFFFFFF / 0x001122334455FFFF |
| subq %rax, %rdx 를 C 로 | `d -= a` (rdx = rdx − rax) |
| long a[i] 를 %rax 로 (a=%rdi, i=%rsi) | `movq (%rdi,%rsi,8), %rax` |
| x86-64 에서 32비트 프로그램이 도는 이유 | IA-32 하위 호환 |

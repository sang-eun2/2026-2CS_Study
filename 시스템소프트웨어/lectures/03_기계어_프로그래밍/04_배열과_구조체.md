# 04. 데이터: 배열, 다차원 배열, 구조체, 정렬 (7-1. Data)

> 출처: `2026-2/시스템소프트웨어/7-1. data.pdf` (CS:APP 3.8~3.9)

## 한눈에 보기
> 어셈블리에는 배열도 구조체도 없다. 모두 **시작 주소 + 오프셋**으로 풀린다. 이름은 사라지고 오프셋과 크기만 남는다.

| 주제 | 핵심 |
|---|---|
| 1차원 배열 | 주소 = B + 원소 크기 × i, 명령 하나 |
| 다차원 배열 | **행 우선**: 주소 = B + 크기 × (C·i + j) |
| 포인터 배열 | 메모리 접근이 한 번 더. 행 길이가 다를 때만 유리 |
| 구조체 | 필드 이름 → 오프셋 상수 |
| 정렬 | K 바이트 자료형은 K 의 배수 주소. 사이와 끝에 패딩 |
| 필드 순서 | 큰 것부터 놓으면 패딩 감소 |

---

## Part A. 배열
### 1차원
`T A[N];` → sizeof(T) × N 연속 공간, **A[i] 주소 = B + sizeof(T) × i**

| 선언 | 원소 크기 | 전체 |
|---|---|---|
| char A[12] | 1 | 12 |
| char *B[8] | 8 | 64 |
| int C[6] | 4 | 24 |
| double *D[5] | 8 | 40 |

```asm
# int get(int *a, long i) { return a[i]; }
get: movl (%rdi,%rsi,4), %eax
     ret
```
- C 는 **범위 검사를 안 한다** → 버퍼 오버플로의 출발점

### 배열 ≠ 포인터
```c
int a[4] = {1,2,3,4};  int *p = a;
```
| | a | p |
|---|---|---|
| 담는 것 | 원소 4개 | 주소 1개 |
| sizeof | 16 | 8 |
| 다른 주소 대입 | 불가 | 가능 |
- 함수에 넘기면 **시작 주소만** 간다 → 함수 안 `sizeof p` = 8 → 길이 n 을 같이 넘김. 매개변수 `int p[]` ≡ `int *p`

### 다차원 배열: 행 우선
`T A[R][C];` → **주소 = B + sizeof(T) × (C·i + j)**
```asm
# int get2(int A[3][4], long i, long j) { return A[i][j]; }
get2:
    salq $4, %rsi            # 16*i (한 행 = 4 × 4 = 16바이트)
    addq %rsi, %rdi          # 이 행의 시작
    movl (%rdi,%rdx,4), %eax # + 4*j
    ret
```
- C 식 `A + 1` 은 한 행(16바이트) 이동
- Fortran 은 열 우선
- 성능: **j 를 안쪽 루프**로 돌아야 메모리를 순서대로 읽어 캐시 적중 (13주차)

### 배열의 배열 vs 포인터 배열
```c
int A[3][4];   // 한 덩어리 48바이트
int *B[3];     // 포인터 3개(24바이트) + 흩어진 각 행
```
| | 메모리 접근 | 계산 |
|---|---|---|
| `A[i][j]` | **1번** | 주소 산술 |
| `B[i][j]` | **2번** | 행 포인터 읽고 다시 |
```asm
movq (%rdi,%rsi,8), %rax   # B[i] (행 포인터)
movl (%rax,%rdx,4), %eax   # B[i][j]
```
행 길이가 같으면 배열의 배열, 다르면 포인터 배열

## Part B. 구조체와 정렬
### 필드 오프셋
```c
struct rec { int a[4]; size_t i; struct rec *next; };   // a: 0, i: 16, next: 24
```
```asm
get_i:  movq 16(%rdi), %rax         # r->i
        movl (%rdi,%rsi,4), %eax    # r->a[i] (a 는 오프셋 0)
.L11:   movq 24(%rdi), %rdi         # r = r->next
        testq %rdi, %rdi
        jne .L11                    # NULL 아니면 반복
```

### 정렬 규칙
| 자료형 | K | 주소 조건 |
|---|---|---|
| char | 1 | 아무 데나 |
| short | 2 | 2의 배수 |
| int, float | 4 | 4의 배수 |
| long, double, 포인터 | 8 | 8의 배수 |
- 이유: 메모리는 한 번에 8바이트씩 읽힘. 경계를 걸치면 두 번 읽어 붙여야 함
- **구조체 끝에도 패딩**: 전체 크기가 가장 큰 필드 정렬의 배수여야 (배열로 늘어놓을 때 각 원소가 정렬되도록)

### 같은 필드, 다른 배치
```c
struct S1 { char c; int i[2]; double v; };   // c 0 | 패딩 3 | i 4 | 패딩 4 | v 16 → 24
struct S2 { double v; int i[2]; char c; };   // v 0 | i 8 | c 16 | 끝 패딩 7 → 24
struct S3 { char a; char b; int i; };        // a 0 | b 1 | 패딩 2 | i 4 → 8
```
- 확인: `sizeof`, `offsetof(struct S1, v)` (`<stddef.h>`)
- 큰 필드부터 놓으면 패딩이 줄어든다 (수백만 개 배열에서 큰 차이)
- **구조체를 그대로 파일·네트워크로 보내지 말 것** (패딩과 엔디안이 기계마다 다름)

## 확인 문제 풀이
| 문제 | 답 |
|---|---|
| double D[8], &D[5] 오프셋 | 8 × 5 = **40** |
| int A[4][6], &A[2][3] 오프셋 | 4 × (6·2 + 3) = **60** |
| A[3][4] vs *B[3] 접근 비용 | A 는 주소 계산 후 1번, B 는 행 포인터를 읽고 다시 1번 (2번) |
| struct { char a; double b; char c; } | a 0, b 8, c 16, 크기 **24** (b 앞 패딩 7, 끝 패딩 7) |
| 정렬이 필요한 이유 | 8바이트 단위로 읽으므로 경계를 걸치면 두 번 읽어야 함 |
| 선언 순서에 따라 크기가 다른 이유 | 각 필드 정렬을 맞추는 패딩 위치·양이 달라짐 |
| 행 우선과 이중 루프 | 안쪽 루프를 열 인덱스로 돌아야 연속 접근 → 캐시 적중 |
| 구조체를 파일에 그대로 저장하면 안 되는 이유 | 패딩, 엔디안이 기계마다 다름 |
| 범위 검사가 없는 위험 | 배열 밖 쓰기로 옆 변수·복귀 주소 덮어쓰기 (버퍼 오버플로) |

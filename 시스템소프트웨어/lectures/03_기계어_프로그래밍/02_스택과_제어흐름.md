# 02. 스택과 제어 흐름: push/pop, 조건 코드, 분기, 반복, switch (5-1. Stack and Control)

> 출처: `2026-2/시스템소프트웨어/5-1. stack_and_control (2).pdf` (CS:APP 3.6, 3.7 앞부분)

## 한눈에 보기
> 어셈블리에는 **if 도 for 도 없다.** 연산이 남긴 **조건 코드(플래그)** 를 `cmp`/`test` 로 만들고, **조건 점프**로 건너뛰거나 되돌아가며 모든 제어 구조를 만든다.

| 주제 | 핵심 |
|---|---|
| 메모리 배치 | 코드·데이터·힙(↑)·스택(↓). 힙과 스택이 마주 보며 자람 |
| push/pop | `%rsp` 를 8씩 줄이고/늘림 |
| 조건 코드 | CF ZF SF OF. cmp·test 가 일부러 설정 |
| 조건 분기 | 조건을 **뒤집어** "거짓이면 건너뛰기" |
| 반복 | -Og: 위에서 검사(반복당 점프 2번) / -O1: 진입 검사 + 아래 검사(1번) |
| switch | case 가 촘촘하면 **점프 테이블** |
| 조건부 이동 | 양쪽 다 계산하고 `cmov` 로 고름 (분기 예측 실패 없음) |

## Part A. 스택
### 프로세스 메모리 (높은 주소 → 낮은 주소)
커널(접근 불가) → **스택(아래로 자람: 지역 변수, 호출 정보)** → 빈 공간 → **힙(위로 자람: malloc)** → 데이터(전역 변수) → 코드(읽기 전용)
- 스택과 힙이 마주 보며 자라면 빈 공간을 양쪽이 나눠 써서 낭비가 없다
- 그래서 스택에 넣으면 **%rsp 가 작아진다**

### 섹션과 세그먼트
```c
const char msg[] = "Hi";   // .rodata → 읽기 전용(R) 세그먼트
char       buf[] = "Hi";   // .data   → 읽기·쓰기(RW) 세그먼트
```
- **섹션**: 파일 안 같은 종류 내용의 묶음 / **라벨**: 위치에 붙인 이름 / **세그먼트**: 실행 시 메모리에 놓는 묶음, 접근 권한이 붙음
- **Segmentation fault**: 메모리가 없는 주소 접근, 또는 그 영역이 허용하지 않는 읽기·쓰기·실행. `((char*)msg)[0] = 'B'` 는 컴파일은 되지만 **하드웨어가 막는다** (SIGSEGV, 종료 코드 139)

### push / pop
| 명령 | 동작 |
|---|---|
| `pushq Src` | ① %rsp −= 8 ② M[%rsp] = Src |
| `popq Dest` | ① Dest = M[%rsp] ② %rsp += 8 |
- push/pop 은 1바이트 (`push %rbx` = 53, `pop %rbx` = 5b, `push %r12` = 41 54)
- pop 해도 값은 남지만 %rsp 아래라 언제든 덮어써짐
- 스택의 쓰임: **복귀 주소**, 레지스터 임시 보관, 지역 변수·배열, 7번째 이후 인자

### %rsp 와 %rbp
- **%rsp(Stack Pointer)**: 스택의 끝, push/pop 마다 움직임
- **%rbp(Base Pointer)**: 기준점으로 쓸 때 함수 진입 시 고정 → 지역 변수를 `-8(%rbp)` 처럼 고정 변위로
- %rsp 기준도 가능: 컴파일러가 이동량에 맞춰 변위를 고침 (`24(%rsp)` → push 후 `32(%rsp)`)
- `-O0` 은 거의 늘 `push %rbp; mov %rsp,%rbp`, `-Og` 는 잘 안 씀 (`-fomit-frame-pointer`)

### caller-saved vs callee-saved (System V ABI)
| 구분 | 책임 | 예 |
|---|---|---|
| **caller-saved** | 호출 뒤에도 필요하면 **호출하는 쪽**이 보관 | %rdx |
| **callee-saved** | **호출되는 쪽**이 바꿨다면 반환 전 원래 값으로 복원 | %rbx |
- sumstore 에서 dest(%rdx)를 %rbx 로 옮기는 이유: plus 가 %rdx 를 바꿔도 되돌릴 의무가 없으니까. 대신 sumstore 도 main 에게는 callee 라 %rbx 원래 값을 push/pop 으로 지킨다

### call / ret 과 스택
- `call` = **복귀 주소(call 다음 명령 주소)를 push** 하고 목적지로 점프 / `ret` = 그 주소를 pop 해서 점프
- 거리 = 목적지 − 다음 명령: `call sumstore` 0x115b − 0x1218 = −0xbd → `43 ff ff ff`, `call plus` → `f2 ff ff ff`
- GDB 로 확인: plus 진입 시 `x/1gx $rsp` = 0x555555555164 (= 기준주소 0x555555554000 + 0x1164), `finish` 후 %rsp 는 들어오기 전 값으로 복원, 반환값 123

### red zone
- **다른 함수를 부르지 않는 함수**는 %rsp 아래 **128바이트**를 `subq` 없이 사용 (x86-64 리눅스 ABI)
- call 이 있으면 못 씀 (복귀 주소가 그 자리를 덮음)

## Part B. 조건과 분기
### 조건 코드 (플래그)
| 플래그 | 1 이 될 때 |
|---|---|
| **CF** | 올림(뺄셈은 빌림) — unsigned 넘침 |
| **ZF** | 결과가 0 |
| **SF** | 결과가 음수 |
| **OF** | 2의 보수 오버플로 — signed 넘침 |
- 대부분의 산술·논리 명령이 자동 설정. **leaq 는 설정 안 함** (주소 계산이 조건에 영향 주면 안 되므로)
- 예 (%rax=5): `subq $5` → 0, ZF=1 / `subq $7` → −7, CF=1(빌림), SF=1, OF=0

### 세우는 명령: cmp, test (결과 저장 안 함)
| 명령 | 계산 | 짝 |
|---|---|---|
| `cmpq S, D` | **D − S** | subq |
| `testq S, D` | D & S | andq |
- ⚠️ `cmpq %rsi, %rdi` 는 **rdi − rsi** (x − y)
- `testq %rax, %rax` = `cmpq $0, %rax` 와 같은 효과, 더 짧음. n & n = n 이라 SF 는 부호, ZF 는 0 여부. CF·OF 는 0
- SF=0 만으로는 양수가 아님(0 도 SF=0) → `jle` 는 ZF 와 SF 를 같이 봄

### 읽는 명령: setX (값으로), jX (점프로)
```asm
cmpq %rsi, %rdi     # a - b
setl %al            # signed a < b 면 1
movzbl %al, %eax    # 나머지를 0 으로 → return a < b
```
| 조건 | signed | unsigned |
|---|---|---|
| < | `setl` / `jl` (less) | `setb` / `jb` (below) |
| <= | `le` | `be` |
| > | `g` (greater) | `a` (above) |
| >= | `ge` | `ae` |
| == / != | `e` / `ne` (부호 무관) | |
| < 0 | `s` (SF=1) | |

- a = −1, b = 1: `setl` → 1 (−1 < 1), `setb` → 0 (2⁶⁴−1 < 1 거짓) — **비트는 같고 질문이 다르다**
- **signed "작다" = SF ≠ OF**, unsigned "작다" = CF
  - 8비트 127 < −1 ? → 0x7F − 0xFF = 0x80: SF=1 이지만 **OF=1**(넘쳐서 부호 뒤집힘) → 거짓. unsigned 로는 127 < 255 라 CF=1

### 조건 분기: 조건을 뒤집는다
```c
long absdiff(long x, long y) { return x < y ? y - x : x - y; }
```
```asm
absdiff:
    movq %rsi, %rax
    cmpq %rsi, %rdi     # x - y
    jge  .L6            # x >= y 면 건너뜀 (C 는 x < y)
    subq %rdi, %rax     # y - x
    ret
.L6:
    subq %rsi, %rdi     # x - y
    movq %rdi, %rax
    ret
```
- 참인 쪽에는 점프가 없어 흐름이 끊기지 않게 하려고 **반대 조건으로 건너뜀**
- absdiff(3,10): 3−10=−7, SF=1≠OF=0 → 안 뜀 → 7 / absdiff(10,3): SF=OF=0 → 뜀 → 7
- `jge` 바이트 `7d 04`: 다음 명령 0x25 + 4 = 0x29 로

### 반복
| | 모양 | 반복당 점프 | n = 0 |
|---|---|---|---|
| **do-while** | 본문 → **아래에서 검사** | 1번 (jl) | 본문 한 번 실행됨 |
| **while / for (-Og)** | **위에서 검사** → 본문 → jmp 위로 | 2번 (jge + jmp) | 0번 |
| **-O1 (guarded-do)** | 진입 검사 한 번 + do-while | 1번 (jne) | 0번 |

```asm
# for (i = 0; i < n; i++) s += a[i];   (-Og)
.L2: cmpq %rsi, %rax        # i - n
     jge  .L4               # i >= n 이면 탈출
     addq (%rdi,%rax,8), %rdx
     addq $1, %rax
     jmp  .L2               # eb f1: 0x19 − 0xf = 0xa (뒤로 가는 음수 거리)
```
- **-O1 에선 i 가 사라짐**: 주소 p 를 8씩 늘리고 끝 주소와 비교 → `addq (%rax),%rdx; addq $8,%rax; cmpq %rcx,%rax; jne`
- while 이든 for 든 같은 어셈블리로 모인다. **do-while 이 원형**

### && 와 || = 단축 평가 = 점프
```asm
# return (x > 0 && y > 0) ? x + y : -1;   (-O1)
testq %rdi, %rdi
jle   .L3           # x <= 0 이면 끝 (오른쪽 계산 안 함)
testq %rsi, %rsi
jle   .L3
leaq  (%rdi,%rsi), %rax
ret
.L3: movq $-1, %rax
```
- `p && *p` 가 안전한 이유. -Og 에선 y > 0 을 미리 계산(setg 로 합침)하기도 — 부작용 없는 경우에만 가능

### switch: 점프 테이블
```c
switch (n) {
case 1: result = x*13; break;
case 2: result = x+10;          /* break 없음 → case 3 으로 */
case 3: result = result+11; break;
case 5: case 7: result = x*x; break;
default: result = 0;
}
```
```asm
cmp  $7, %rsi
ja   <default>                  # unsigned 비교: n > 7 과 음수를 한 번에 거름
jmp  *0x402008(,%rsi,8)         # 간접 점프: 표의 n 번 칸에 든 주소로
```
- 표 = case 코드 주소의 배열 (칸당 8바이트 → 배율 8). 3번 칸 주소 0x402008 + 24 = **0x402020**, 그 안의 값 **0x401120** = case 3 코드
- case 없는 칸(0, 4, 6) = default 주소, case 5·7 = 같은 주소
- x=10: n=3 → 21, n=2 → 20 후 fall-through → 31, n=5/7 → 100
- case 값이 **좁은 범위에 촘촘할 때** 사용. 장점: 분기 여러 번 대신 한 번에 이동

### 조건부 이동 (cmov)
```asm
# absdiff, -O1
movq %rsi, %rdx;  subq %rdi, %rdx    # y - x
movq %rdi, %rax;  subq %rsi, %rax    # x - y
cmpq %rsi, %rdi
cmovl %rdx, %rax                     # x < y 면 y - x 선택
ret
```
| | 분기 | cmov |
|---|---|---|
| 계산 | 한쪽만 | 양쪽 다 |
| 점프 | 있음 | 없음 |
| 예측 실패 비용 | 수십 사이클 | 없음 |
- 못 쓰는 경우: 한쪽이 비싸거나, **부작용**이 있을 때 — `p ? *p : 0` 을 cmov 로 하면 p 가 NULL 일 때도 `*p` 를 읽어 터짐

## -Og / -O0 / -O1 과 -g
- `-O0`: 최적화 거의 끔 / `-Og`: 디버깅 편의 고려한 일부 최적화 / `-O1`: 시간·크기 최적화
- `-g` 는 디버깅 정보(소스 줄, 변수) — 최적화 수준과 독립

## 확인 문제 풀이
| 문제 | 답 |
|---|---|
| 스택·힙이 마주 보며 자라는 이유 | 빈 공간을 양쪽이 나눠 써 한쪽만 많이 쓰는 프로그램도 낭비 없음 |
| pushq %rax 후 %rsp | 8 감소 |
| popq 후 그 자리 값 | 남아 있지만 %rsp 아래라 다음 push 에 덮어써짐 |
| x < y 인데 jge 인 이유 | 참인 쪽을 점프 없이 이어 실행하려고 반대 조건으로 건너뜀 |
| -O1 이 점프 한 번인 이유 | 진입 검사 후 검사를 아래로 보내 jmp 가 사라짐 (guarded-do) |
| jg 와 ja 가 나뉜 이유 | 같은 비트를 signed(SF,OF)/unsigned(CF)로 다르게 비교해야 해서 |
| leaq 가 플래그를 안 바꾸는 장점 | cmp 와 jX 사이에 주소 계산을 끼워도 조건이 안 깨짐 |
| cmov 를 못 쓰는 경우 | `p ? *p : 0` 처럼 한쪽에 부작용·오류 가능성이 있을 때 |

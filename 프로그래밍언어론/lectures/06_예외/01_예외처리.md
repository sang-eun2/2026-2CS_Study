# 01. 예외 처리 (Lecture 10: Exception Handling)

> 출처: `2026-2/프로그래밍언어론/Lecture10_Exception.pdf`

## 한눈에 보기
- **예외** = 심각하지 않은 오류·비정상 상황. 처리하면 실행을 이어가고, 처리 안 하면 프로그램 종료
- 필요한 문법 3가지: **정의 / 발생 / 처리**
- 처리 후 흐름: **재개 모델**(발생 지점 다음으로 복귀) vs **종료 모델**(try 블록을 끝내고 다음 문장) — Java, Python, C++ 는 **종료 모델**
- 처리되지 않은 예외는 **호출 스택을 거슬러 전파**된다
- Java: **검사 예외**는 try-catch 로 처리하거나 `throws` 로 선언해야 컴파일된다

---

## 1. 예외 처리 모델
```
try {
    raise E;   (1)
    ...        (2)
} catch (E) {
    ...        (3)
}
...            (4)
```
| 모델 | 실행 순서 | 설명 |
|---|---|---|
| **재개(Resumption)** | (1) → (3) → (2) | 처리 후 예외가 난 곳 다음부터 계속 |
| **종료(Termination)** | (1) → (3) → (4) | 처리 후 try 블록은 끝내고 다음 문장으로 |

## 2. 언어 S 에 예외 추가
```
<command> → ... | exc id;                          // 예외 정의
<stmt>    → ... | raise id;                        // 예외 발생
                | try <stmt> catch(id) <stmt>      // 예외 처리
```
- try 블록에서 난 예외가 catch 의 id 와 같으면 처리, 처리 안 되면 프로그램 종료, 예외가 없으면 다음 문장으로
```
exc InvalidInput;
let int x=0; int y=1; in
    read x;
    try {
        if (x < 0) then raise InvalidInput;
        else while (x != 0) { y = y * x; x = x - 1; }
        print y;
    } catch(InvalidInput) print "invalid input";
end;
```
- 여러 catch 는 try 를 중첩한 것과 같다
```
try S1 catch(E1) S2 catch(E2) S3   ≡   try (try S1 catch(E1) S2) catch(E2) S3
```

## 3. Python 예외
```python
try:
    x = int(input('나눌 수: '))
    print(10 / x)
except ZeroDivisionError as e:      # 0 입력
    print('0으로 나눌 수 없음:', e)
except ValueError as e:             # '10.0' 같은 정수 아닌 입력
    print('정수가 아님:', e)
finally:                            # 예외 여부와 상관없이 마지막에 항상 실행
    print('try 문 끝')
```
- `except:` 나 `except Exception:` 처럼 포괄적으로 잡으면 예외별로 적절히 처리하기 어렵다
- **발생**: `raise ZeroDivisionError('메시지')`
- **정의**: `Exception` 을 상속한 클래스, 메시지는 `__str__` 으로
```python
class NegativeInputException(Exception):
    def __str__(self):
        return "Negative input."
```

### 예외 전파
```python
def C(x): return 8 / x          # x = 0 이면 예외
def B(y): return C(y - 1)       # y = 1 이면 C 에서 예외
def A():
    try: print(B(int(input())))
    except ZeroDivisionError: print('0으로 나눌 수 없음')
A()   # 1 입력 → C 에서 발생 → B 를 거쳐 A 에서 처리
```
처리하지 않으면 트레이스백에 A → B → C 호출 경로가 찍히고 종료된다.

## 4. Java 예외
- 예외 타입 = **클래스** (`Exception` 또는 하위 클래스 상속) → 생성자·필드·메소드 가능
- 예외 객체는 **일급 객체**: 일반 객체처럼 쓸 수 있고, 다른 점은 **던질(throw) 수 있다**는 것
- 발생은 `throw 예외객체;` (메소드 헤더의 `throws` 와 다름)
- 대표 예외: `ArithmeticException`(0으로 나눔, RuntimeException 하위), `ArrayIndexOutOfBoundsException`, `NegativeArraySizeException`, `NullPointerException`

```java
class NegativeInputException extends Exception { ... }

try {
    while (true) {
        newGrade = scan.nextInt();
        if (newGrade < 0) throw new NegativeInputException();
        if (newGrade <= 100) total += newGrade;
        else System.out.println("Out of range input !");
    }
} catch (NegativeInputException x) {
    System.out.println("Total:" + total);
} finally { ... }
```

### 전파
처리되지 않은 예외는 호출자 → 그 호출자 … → main() 까지 전파되고, main 에서도 처리 안 되면 종료.
```java
void input() throws NegativeInputException { ... throw new NegativeInputException(); ... }
void via()   throws NegativeInputException { input(); }
main: try { p.via(); } catch (NegativeInputException m) { ... }
```
→ input 에서 발생 시 "input method end", "via method end" 는 출력되지 않고 main 의 catch 로 간다 (종료 모델).

## 5. 컴파일러의 예외 검사 (Java)
메소드 안에서 발생 가능한 예외에 대해
1. 처리할 try-catch 가 있는지 확인
2. 없으면 메소드 헤더에 `throws` 로 선언됐는지 확인
3. 다른 메소드를 호출하면 그 메소드의 `throws` 목록을 보고 같은 검사
→ 어기면 "~Exception must be caught or declared to be thrown" 오류

| | **검사 예외 (Checked)** | **비검사 예외 (Unchecked)** |
|---|---|---|
| 범위 | RuntimeException 을 **제외한** 모든 예외 | `RuntimeException` 하위 표준 실행시간 예외 |
| 컴파일러 검사 | 처리/선언 여부를 **미리 검사** | 검사 안 함, 프로그래머 책임 |
| 미처리 시 | `throws` 선언 필수 | 선언 필요 없음 |

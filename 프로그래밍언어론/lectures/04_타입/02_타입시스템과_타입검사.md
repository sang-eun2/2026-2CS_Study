# 02. 타입 시스템과 타입 검사 (Lecture 7: Type System)

> 출처: `2026-2/프로그래밍언어론/Lecture07_TypeSystem.pdf`

## 한눈에 보기
- **타입 오류**: 문법은 맞지만 타입을 잘못 쓴 것 (`x = !x + 2` 에서 x 가 int)
- **정적 타입 검사**: 실행 전에 타입 오류를 미리 찾아 안전하게 실행
- **타입 규칙** = 논리 추론 규칙 `가정들 / 결론`, **타입 시스템** = 타입 규칙의 모음
- 변수가 있으면 **타입 환경 Γ : Identifier → Type** 이 필요
- **안전한(sound) 타입 시스템**: 타입 검사를 통과하면 실행 중 타입 오류가 절대 없다

| 주제 | 이론 | 구현 |
|---|---|---|
| 구문 | 문법 | 파서 |
| 의미 | 의미 함수 | 인터프리터 |
| **타입** | **타입 규칙** | **타입 검사기** |

---

## 1. 타입 오류와 타입 검사
타입 오류 예
```
int x = 1;  bool y = true;
y = x;          // int 를 bool 에
x = x + y;      // int + bool
fun bool f(int x) if (x>0) then return 1; else return 0;   // bool 함수가 int 반환
```
- 구문 분석: 1970년대 1세대 기술, 모든 언어에 적용
- 타입 검사: 1990년대 이후 2세대 기술 (안전한 타입 시스템: Java, C#, ML, Haskell, Smalltalk)

| 검사 방식 | 시점 | 언어 |
|---|---|---|
| 정적 타입 검사 | 컴파일 시간 | Java, Pascal, C, C++, ML, Haskell |
| 동적 타입 검사 | 실행 시간 | Lisp, Scheme |
| 검사 없음 | - | 어셈블리 |

### 안전한(Sound) 타입 시스템
- `⊢ E : t` 이고 E 를 계산한 값이 v 이면 **v 는 반드시 t 타입**
- 포함 관계: **타입 검사 통과 프로그램 ⊆ 실행 중 타입 오류 없는 프로그램 ⊆ 문법에 맞는 프로그램**
  - 통과했는데 오류가 나는 경우(거짓 양성)가 없다

| 수준 | 언어 | 이유 |
|---|---|---|
| 안전하지 않음 | C, C++ | 타입 캐스팅, 포인터 연산 |
| 거의 안전 | Pascal, Ada | 허상 포인터(dangling pointer) |
| **안전** | ML, Java | 컴파일 시 엄격히 검사 |

## 2. 타입 규칙 표기
"E1 이 int 이고 E2 가 int 이면 E1 + E2 는 int"
```
 Γ ⊢ E1 : int    Γ ⊢ E2 : int        (가정들)
──────────────────────────────        
      Γ ⊢ E1 + E2 : int               (결론)
```
`Γ ⊢ E : t` 는 "타입 환경 Γ 에서 E 의 타입은 t" 라고 읽는다.

## 3. 언어 S 의 타입 규칙 (시험 핵심)
| 대상 | 규칙 | 의미 |
|---|---|---|
| 상수 | Γ ⊢ n : int, Γ ⊢ true : bool | |
| 변수 | Γ(id) = t **/** Γ ⊢ id : t | 환경에서 타입을 찾음 |
| 산술식 | Γ ⊢ E1:int, Γ ⊢ E2:int **/** Γ ⊢ E1+E2 : int | |
| 관계식 | Γ ⊢ E1:t, Γ ⊢ E2:t **/** Γ ⊢ E1==E2 : bool | **같은 타입** t 끼리 비교 |
| 대입문 | Γ ⊢ id:t, Γ ⊢ E:t **/** Γ ⊢ id = E : **void** | 결과값 없음 |
| let 문 | Γ ⊢ E:t, **Γ[id ↦ t]** ⊢ S:t' **/** Γ ⊢ let t id = E in S end : t' | 블록 안에서만 id 추가 |
| return | Γ ⊢ E:t **/** Γ ⊢ return E : t | 반환값 타입 |
| if 문 | Γ ⊢ E:**bool**, Γ ⊢ S1:t, Γ ⊢ S2:t **/** Γ ⊢ if E then S1 else S2 : t | 두 분기 **같은 타입** |
| 복합문 | Γ ⊢ S1:**void**, Γ ⊢ S2:t **/** Γ ⊢ S1; S2 : t | **return 뒤에 다른 문장 금지** |
| while 문 | Γ ⊢ E:**bool**, Γ ⊢ S:**void** **/** Γ ⊢ while (E) S : void | **루프 안 return 금지** |
| read / print | Γ ⊢ id:t **/** read id : void, Γ ⊢ E:t **/** print E : void | |

### 예제 판정
| 코드 | 결과 | 이유 |
|---|---|---|
| `let bool x; in x = 1; end;` | ❌ | bool 변수에 int 대입 |
| `let int x = 0; in x = x + 1; end;` | ✅ void | |
| `fun bool f(int x) if (x>0) then return 1; else return false;` | ❌ | 두 분기 타입이 int, bool 로 다름 |
| `fun bool f(int x) if (x>0) then return true; else return false;` | ✅ bool | |
| `{ if ... return true; else return false; x = x - 1; }` | ❌ | return 뒤에 문장 (S1 이 void 가 아님) |
| `{ x = x - 1; if ... return true; else return false; }` | ✅ bool | |
| `while (x>0) { ...; return y; }` | ❌ | 루프 안 return |
| `while (x>0) { ... } return y;` | ✅ int | |

### 유도 트리 예
```
{ } ⊢ let int x = 0 in x = x + 1 end : void
 ├ { } ⊢ 0 : int
 └ {x↦int} ⊢ x = x + 1 : void
     ├ {x↦int} ⊢ x : int
     └ {x↦int} ⊢ x + 1 : int
         ├ {x↦int} ⊢ x : int
         └ {x↦int} ⊢ 1 : int
```

## 4. 타입 검사기 구현
- 타입 환경은 **스택(심볼 테이블)** 으로 구현: `class TypeEnv extends Stack<Entry>` (Entry = id + type)
  - 함수도 넣는다: Γ = {y ↦ int, f ↦ int → bool}
- AST 를 순회하며 Stmt/Expr 마다 해당 규칙을 적용하고, 어기면 오류 메시지 출력
```java
static Type Check(Binary b, TypeEnv te) {
    Type t1 = Check(b.expr1, te), t2 = Check(b.expr2, te);
    switch (b.op.val) {
        case "+": case "-": case "*": case "/":
            if (t1 == Type.INT && t2 == Type.INT) b.type = Type.INT;
            else error(b, "type error for " + b.op);
            break;
        case "<": case "<=": ...
            if (t1 == t2) b.type = Type.BOOL;
            else error(b, "type error for " + b.op);
            break;
    }
    return b.type;
}

static Type Check(Assignment a, TypeEnv te) {
    if (!te.contains(a.id)) { error(a, "undefined variable"); return Type.ERROR; }
    if (te.get(a.id) == Check(a.expr, te)) a.type = Type.VOID;
    else error(a, "mixed mode assignment to " + a.id);
    return a.type;
}

static Type Check(If c, TypeEnv te) {
    Type t = Check(c.expr, te), t1 = Check(c.stmt1, te), t2 = Check(c.stmt2, te);
    if (t != Type.BOOL)  error(c, "non-bool test in condition");
    else if (t1 != t2)   error(c, "non-equal type in two branches");
    else c.type = t1;
    return c.type;
}

static Type Check(While l, TypeEnv te) {
    Type t = Check(l.expr, te), t1 = Check(l.stmt, te);
    if (t != Type.BOOL)       error(l, "non-bool test in loop");
    else if (t1 != Type.VOID) error(l, "return in loop..");
    else l.type = t1;
    return l.type;
}

static Type Check(Let l, TypeEnv te) {
    addType(l.decls, te);              // 선언 변수 타입 push
    l.type = Check(l.stmts, te);
    deleteType(l.decls, te);           // 블록 끝나면 pop
    return l.type;
}

static Type Check(Decl d, TypeEnv te) {   // 초기화식 타입이 선언 타입과 같은지
    if (d.arraysize == 0 && d.expr != null && d.type != Check(d.expr, te))
        error(d, "type error: incorrect initialization to " + d.id);
    te.push(d.id, d.type);
    return d.type;
}
```
> 💡 인터프리터의 `State`(변수 → 값)와 타입 검사기의 `TypeEnv`(변수 → 타입)는 구조가 같다. 둘 다 블록 시작에 push, 끝에 pop 한다.

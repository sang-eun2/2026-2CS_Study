# 01. 구문과 문법 (Lecture 2: Syntax)

> 출처: `2026-2/프로그래밍언어론/Lecture02_Syntax.pdf`

## 한눈에 보기
- 무한한 문장을 유한하게 정의하는 방법 = **재귀적 정의 → 문맥자유문법(CFG)**
- 문장이 문법에 맞는지 확인 = **유도(derivation)** 가 가능한지 보는 것
- 유도 과정을 트리로 그린 것 = **파스 트리**
- 같은 문장에 파스 트리가 2개 이상 → **모호한 문법** → 우선순위 도입 또는 문법 수정으로 해결
- 문법을 그대로 함수로 옮긴 파서 = **재귀 하강 파서**

---

## 1. 재귀적 정의: 이진수 예시
```
D → 0 | 1          (숫자)
N → D | N D        (이진수: 숫자 하나, 또는 이진수 뒤에 숫자)
```
**의미(값) 함수** V 를 구문 규칙마다 붙일 수 있다.
```
V('0') = 0, V('1') = 1
V(ND) = V(N) * 2 + V(D)
V('101') = V('10')*2 + V('1') = (1*2+0)*2 + 1 = 5
```
십진수는 `* 2` 대신 `* 10`.

## 2. 문맥자유문법 (CFG)
구성 요소 4가지:
1. 터미널 기호 집합 **T** (토큰, 보통 소문자)
2. 논터미널 기호 집합 **N** (보통 대문자)
3. 시작 기호 **S** (N 중 하나)
4. 생성 규칙: `X → Y1 Y2 … Yn` (X ∈ N, Yi ∈ T ∪ N), 빈 문자열은 `X → ε`

언어 S 의 문장 문법(요약):
```
S → id = E | S ; S | if E then S | if E then S else S
  | while (E) S | read id | print E
E → n | id | true | false | E+E | E-E | E*E | E/E | (E)
  | E==E | E!=E | E<E | E>E | !E
```

## 3. 유도 (Derivation)
- 시작 기호에서 출발해 논터미널을 규칙의 오른쪽으로 바꾸는 과정을 **논터미널이 없어질 때까지** 반복
- **유도할 수 있으면 문법에 맞는 문장, 없으면 틀린 문장**
- `⇒` : 직접 유도(규칙 1번), `⇒*` : 여러 번
- 예: `S → aS | b` 이면 `S ⇒ aS ⇒ aaS ⇒ aaaS ⇒ aaab`

| 종류 | 매 단계에서 바꾸는 논터미널 |
|---|---|
| **좌측 유도** | 가장 왼쪽 |
| **우측 유도** | 가장 오른쪽 |

- 문법 G 가 정의하는 언어 **L(G)** = G 로 유도 가능한 모든 터미널 문자열의 집합
  - 예: `S → (S) | a` 이면 L(G) = { (ⁿ a )ⁿ | n ≥ 0 }

### 파스 트리 (유도 트리 = 구문 트리)
- 루트 = 시작 기호, 규칙 `X → Y1…Yn` 을 적용하면 X 아래에 Y1…Yn 이 자식으로 붙음

### 연습문제 정답 모음
| 문법 | 문자열 | 유도 |
|---|---|---|
| `S → Sa \| b` | baaa | S ⇒ Sa ⇒ Saa ⇒ Saaa ⇒ baaa |
| `S → aSb \| c` | aaacbbb | S ⇒ aSb ⇒ aaSbb ⇒ aaaSbbb ⇒ aaacbbb |
| `S → AaBb, A → Ab\|b, B → aB\|a` | 짧은 순 6개 | baab, bbaab, baaab, bbbaab, baaaab, bbaaab → 언어는 `bb*aaa*b` |

## 4. 모호성 (Ambiguity)
- **모호한 문법**: 어떤 문자열에 대해 좌측 유도(또는 우측 유도, 파스 트리)가 **2개 이상** 존재
- 왜 나쁜가? 같은 문장을 두 가지로 해석할 수 있어 의미가 갈린다
- 예: `E → E*E | E+E | (E) | N` 에서 `3 + 4 * 5` 는 (3+4)*5 와 3+(4*5) 두 트리가 나온다

### 해결 방법 1: 문법 재작성 (같은 언어, 모호성 제거)
연산자 우선순위를 층(level)으로 나눈다. 아래층일수록 먼저 계산된다.
```
E → E + T | T      (덧셈: 가장 늦게)
T → T * F | F      (곱셈)
F → N | (E)        (숫자·괄호: 가장 먼저)
```
- **좌재귀(E → E + T)** 로 쓰면 **좌결합**이 된다
- 예: `E → E - E | id` (모호) → `E → E - T | T, T → id` (모호성 제거 + 좌결합)

### 해결 방법 2: 언어 일부 변경 — dangling else
- `if e1 then if e2 then s1 else s2` 에서 else 가 어느 if 에 붙는지 모호
- 문법에 `end` 를 넣어 구분: `S → if E then S end | if E then S else S`

## 5. BNF / EBNF / 구문 도표
| 표기 | 의미 |
|---|---|
| BNF | `<expr> → <expr> + <term> \| <term>` (재귀로 반복 표현) |
| EBNF `[ ]` | 0번 또는 1번 (선택) |
| EBNF `{ }` | 0번 이상 반복 |

```
<expr>   → <term> { + <term> }
<term>   → <factor> { * <factor> }
<factor> → number | ( <expr> )
```
- **구문 도표**: 논터미널 = 사각형, 터미널 = 원, 순서 = 화살표, `{ }` 반복 = 루프

## 6. 재귀 하강 파싱 (Recursive-Descent Parsing)
| 주제 | 이론 | 구현물 |
|---|---|---|
| 구문 | 문법 | **파서** |
| 의미 | 의미 함수 | 인터프리터 |
| 타입 | 타입 규칙 | 타입 검사기 |

규칙: **논터미널 하나 = 함수 하나**, 함수 본문 = 규칙의 오른쪽을 순서대로 (좌측 유도)
```c
// <A> → <B> c <D>
void A() { B(); match('c'); D(); }

// match: 현재 토큰이 기대한 것이면 다음 토큰을 읽고, 아니면 오류
void match(int c) { if (token == c) token = getToken(); else error(); }
```
EBNF `{ }` 는 while 문으로, 파싱하면서 값까지 계산하면 계산기가 된다.
```c
int expr(void) {               // <expr> → <term> {+ <term>}
    int result = term();
    while (token == '+') { match('+'); result += term(); }
    return result;
}
int term(void) {               // <term> → <factor> {* <factor>}
    int result = factor();
    while (token == '*') { match('*'); result *= factor(); }
    return result;
}
```
> 💡 곱셈(term)이 덧셈(expr)보다 **아래 단계 함수**에서 처리되므로 자동으로 우선순위가 높아진다.

### 실습 #1 문법 (Java 계산기 확장)
```
<expr>   → <bexp> {& <bexp> | '|' <bexp>} | !<expr> | true | false
<bexp>   → <aexp> [<relop> <aexp>]
<relop>  → == | != | < | > | <= | >=
<aexp>   → <term> {+ <term> | - <term>}
<term>   → <factor> {* <factor> | / <factor>}
<factor> → [-] ( <number> | (<aexp>) )
```

# 01. 함수, 매개변수 전달, 바인딩 (Lecture 8: Function)

> 출처: `2026-2/프로그래밍언어론/Lecture08_Function.pdf`

## 한눈에 보기
- **프로시저**: 반환값 없음 / **함수**: 반환값 있음, 식 안에 쓸 수 있음 (C·Java·S 는 함수만, 프로시저 = void 함수)
- 매개변수 전달 4가지: **값 / 참조 / 값-결과 / 이름** 전달 → 같은 코드라도 결과가 다르다 (시험 단골)
- **정적 유효범위**(선언 위치 기준) vs **동적 유효범위**(호출 순서 기준)
- **바인딩**: 이름과 속성을 연결. 컴파일 시 = 정적, 실행 중 = 동적. 정보는 **심볼 테이블**에 보관
- 함수 타입 규칙: `Γ[id ↦ t1] ⊢ S : t2 / Γ ⊢ fun t2 f(t1 id) S : t1 → t2`

---

## 1. 언어 S 의 함수 확장
```
<command>  → <decl> | <stmt> | <function>
<function> → fun <type> id( <params> ) <stmt>
<params>   → <type> id {, <type> id}
<type>     → int | bool | string | void
<stmt>     → ... | return <expr>; | id(<expr> {, <expr>});
<factor>   → ... | id(<expr> {, <expr>})
```
```
fun int max(int x, int y) if (x > y) then return x; else return y;
print max(a, b);
```
| 언어 | 프로시저/함수 |
|---|---|
| C, C++, Java, Python, S | 함수만 (프로시저 = void 반환) |
| Ada | 구분함 |
| Modula-2 | 둘 다 procedure, 함수 = 반환값 있는 프로시저 |

## 2. 매개변수 전달
- **형식 매개변수(formal)**: 선언에 쓰인 매개변수 / **실 매개변수(actual, 인자)**: 호출에 쓰인 값
- 매개변수 전달 = 호출 시 둘을 대응시키는 것

| 방식 | 동작 | 특징 |
|---|---|---|
| **값 전달** | 인자 값을 계산해 형식 매개변수에 **복사** | 함수 안 변경이 밖에 영향 없음 → swap 불가 |
| **참조 전달** | 인자의 **주소**를 넘김, 사용 시 자동 역참조 | 형식 매개변수 변경 = 실 매개변수 변경. **별명(aliasing)** 문제. 인자는 변수여야 함 |
| **값-결과 전달** | 호출 시 값 복사(copy-in), **반환 시 다시 복사(copy-out)** | 함수 실행 중에는 별개, 끝날 때만 반영 |
| **이름 전달** | 인자를 **사용할 때까지 계산을 미룸**(지연 평가), 형식 매개변수 자리에 인자 식을 그대로 넣고 실행한다고 생각 | 함수형 언어의 지연 평가 |

### C 에서 참조 효과 내기 (포인터)
```c
void swap(int *px, int *py) { int t = *px; *px = *py; *py = t; }
swap(&a, &b);   // 주소를 넘기고, 역참조는 프로그래머가 직접
```
C++ 참조 매개변수: `void swap(int& x, int& y) { int t = x; x = y; y = t; }`

### ⭐ 같은 코드, 방식별 결과 (교재 예제)
```c
void p(int x, int y) { x++; y++; }
int a = 1;  p(a, a);
```
| 방식 | a | 이유 |
|---|---|---|
| 값 | **1** | 복사본만 증가 |
| 참조 | **3** | x, y 모두 a 의 별명 → a 를 두 번 증가 |
| 값-결과 | **2** | x=2, y=2 가 되고 반환 시 a 에 2 를 복사 |
| 이름 | **3** | `a++; a++;` 로 치환된 것과 같음 |

### 참조 전달의 별명 문제
```c++
int a = 1;
void ack(int& x, int& y) { x = 2; a = 3; y = 4; }
ack(a, a);    // x, y, a 가 모두 같은 변수 → 최종 a = 4
```

### 이름 전달의 함정
```c
int i; int a[10];
void p(int x) { i = i + 1; x = x + 1; }
i = 1; a[1] = 10; a[2] = 20;
p(a[i]);      // x 자리에 a[i] 를 넣어 실행 → i=2 가 된 뒤 a[2] = 21 (a[1] 은 그대로 10)
```
`swap(i, a[i])` 도 `t = i; i = a[i]; a[i] = t;` 로 바뀌어 i 가 먼저 바뀌는 바람에 엉뚱한 원소가 바뀐다.

### 언어별 방식
| 언어 | 방식 |
|---|---|
| Ada | in 매개변수 = 값, in out 매개변수 = 값-결과 |
| C | 값 (포인터로 참조 효과) |
| C++, Pascal, Modula-2 | 값, 참조 |
| Java | 기본형 = 값, 객체 = 참조 |
| FORTRAN | 참조 / Python = 객체 참조 전달 |

## 3. 유효범위 규칙과 함수
| 규칙 | 기준 | 사용 |
|---|---|---|
| **정적 유효범위** | 선언된 **블록(코드 위치)** 안에서만 유효 | 대부분의 언어 |
| **동적 유효범위** | 선언한 블록의 **실행이 끝날 때까지** 유효, 실행 경로에 따라 달라짐 | 옛 Lisp, SNOBOL |

```
1 int x = 0;
2 fun void g(int y)  x = x + y * y;
4 fun void f(int z)
5   let int x = 10; in
6     g(z);
7   end;
8 f(5);
```
| | g 의 x 가 가리키는 것 | 결과 (지역 x, 전역 x) |
|---|---|---|
| 정적 | g 가 **정의된** 곳 바깥 = 전역 x | 지역 x = 10, 전역 x = 25 |
| 동적 | g 를 **호출한** f 의 x | 지역 x = 35, 전역 x = 0 |

## 4. 바인딩과 심볼 테이블
- **바인딩** = 이름과 속성을 연결하는 것
  - 상수 이름 → 실제 값, 변수·함수 → 유효범위·타입, 변수 → 메모리 주소, `*` → 곱셈 연산, 함수 호출 → 호출될 함수
- **정적 바인딩**: 컴파일 시 한 번, 실행 중 불변 (정적 속성)
- **동적 바인딩**: 실행 중, 바뀔 수 있음 (동적 속성)
- 변수 속성: 타입, 유효범위, 값/위치 / 함수 속성: 타입, 유효범위, 코드 위치
- **심볼 테이블(환경)**: 유효한 바인딩 정보를 관리하는 자료구조
  - 컴파일러·타입 검사기: 타입 정보 / 인터프리터: 변수 값, 함수 코드 위치

| ID | Type | Scope | Value |
|---|---|---|---|
| y | int | Global | 25 |
| square | fun int→int | Global | square 의 AST |
| x | int | Local(square) | 5 |

## 5. 함수 타입 검사
| 대상 | 규칙 |
|---|---|
| 함수 정의 | Γ[id ↦ t1] ⊢ S : t2 **/** Γ ⊢ fun t2 f(t1 id) S : **t1 → t2** |
| 재귀 함수 정의 | **Γ[f ↦ t1→t2**, id ↦ t1] ⊢ S : t2 **/** Γ ⊢ fun t2 f(t1 id) S : t1 → t2 (본문에서 자기 자신을 부르므로 f 도 미리 넣음) |
| 함수 호출 | Γ(f) = t1 → t2, Γ ⊢ E : t1 **/** Γ ⊢ f(E) : t2 |

- `fun int square(int x) return x*x;` → int → int ✅
- `fun bool f(int x) if (x>0) then return 1; else return 0;` → 본문이 int 인데 선언은 bool → ❌

## 6. 구현
- AST: `Function = Type type; Identifier id; Decls params; Stmt stmt`, `Call = Identifier id; Exprs args`, `Return = Identifier fid; Expr expr`
```java
private Function function() {
    match(Token.FUN);
    Type t = type();
    String str = match(Token.ID);  funId = str;
    Function f = new Function(str, t);
    match(Token.LPAREN); f.params = params(); match(Token.RPAREN);
    f.stmt = stmt();
    return f;
}

static Type Check(Function f, TypeEnv te) {
    te.push(f.id, new ProtoType(f.type, f.params));   // 재귀 호출 대비
    for (Decl d : f.params) te.push(d.id, d.type);
    Type t = Check(f.stmt, te);                        // 본문 검사
    for (Decl d : f.params) te.pop();
    te.pop();
    if (t == f.type) { te.push(f.id, new ProtoType(f.type, f.params)); return f.type; }
    error(f, "incorrect return type"); return Type.ERROR;
}

static Type Check(Call c, TypeEnv te) {
    if (!te.contains(c.fid)) { error(c, "undefined function: " + c.fid); return c.type; }
    ProtoType p = (ProtoType) te.get(c.fid);
    c.type = p.result;
    // 인자 개수 비교 후, 각 인자 타입 == 매개변수 타입인지 검사
    ...
}
```
> ⚠️ 슬라이드의 Call 검사 코드는 `if (te.contains(c.fid))` 로 되어 있는데, "정의되지 않은 함수" 오류를 내려면 `!te.contains(...)` 가 맞다.

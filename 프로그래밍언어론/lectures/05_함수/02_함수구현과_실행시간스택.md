# 02. 함수 구현과 실행시간 스택 (Lecture 9: Function Implementation)

> 출처: `2026-2/프로그래밍언어론/Lecture09_FunctionImp.pdf`

## 한눈에 보기
- 함수 호출·반환은 **LIFO** → **실행시간 스택**으로 구현
- 호출마다 **활성 레코드(스택 프레임)** 를 새로 만든다 (재귀 때문에 정적 할당 불가)
- 인터프리터: 상태 스택을 실행시간 스택으로 사용 (함수 정의 = 이름+AST push, 호출 = 프레임 생성)
- 컴파일러: **제어 링크**(호출자) + **접근 링크**(정의된 곳, 정적 유효범위) 로 변수를 찾는다

---

## 1. 호출과 반환에 필요한 일
| 호출 시 | 반환 시 |
|---|---|
| 매개변수 메모리 할당 | 지역 변수·매개변수 메모리 해제 |
| 매개변수 전달 | 반환값 저장 |
| 지역 변수 메모리 할당 | 호출자에게 복귀 |
| 반환값·**복귀 주소** 저장 | |
| 피호출 함수 시작으로 제어 이동 | |

## 2. 실행시간 스택과 활성 레코드
- A → B → C 순 호출이면 C → B → A 순으로 끝난다 (**LIFO**)
- **왜 호출마다 새 레코드?** 재귀가 허용되므로 함수가 끝나기 전에 또 호출될 수 있다 → 정적으로 하나만 잡아 둘 수 없다

### 활성 레코드(스택 프레임) 구성
```
  ← Stack Pointer
┌───────────────┐
│ 반환값         │
│ 지역 변수      │
│ 매개변수       │
│ 복귀 주소      │
│ 제어 링크      │ ← 호출자의 활성 레코드를 가리킴 (동적 링크)
└───────────────┘ ← Frame Pointer
```
- `print fact(3);` → fact(3), fact(2), fact(1) 프레임이 쌓였다가 역순으로 사라진다

## 3. 인터프리터에서의 함수 구현
상태 스택 = 실행시간 스택.

| 상황 | 동작 |
|---|---|
| **함수 정의** | `(함수 이름, 함수 AST)` 를 상태 스택에 push |
| **함수 호출** | ① 스택에서 함수 AST 찾기 ② 프레임 만들고 인자 계산·전달 ③ 본문 실행 ④ 반환값은 프레임 맨 위에서 꺼냄 ⑤ 프레임 제거 |
| **return** | 식의 값을 계산해 프레임의 반환값 자리에 저장 |

```java
State Eval(Command p, State state) {           // 함수 정의
    if (p instanceof Function) {
        Function f = (Function) p;
        state.push(f.id, new Value(f));        // Value 가 함수도 담음 (Type.FUN)
        return state;
    }
}

Value V(Call c, State state) {                 // 값을 돌려주는 함수 호출
    Value v = state.get(c.fid);                // 함수 AST 가져오기
    Function f = v.funValue();
    State s = newFrame(state, c, f);           // 프레임 추가
    s = Eval(f.stmt, s);                       // 본문 실행
    v = s.peek().val;                          // 반환값 꺼내기
    s = deleteFrame(s, c, f);                  // 프레임 제거
    return v;
}
```
### newFrame / deleteFrame
- newFrame: ① 인자 값 계산 ② 형식 매개변수 메모리 할당 ③ 인자 값 복사 ④ **매개변수 바로 위에 반환값 항목** 추가
- 지역 변수: 언어 S 에서는 `let` 이 관리 → 반환값 위에 할당되고 let 이 끝나면 해제
- deleteFrame: 반환값 항목 제거 → 매개변수 해제(free)

### 정적 유효범위 구현
```
1 int x = 0;
2 fun void g(int y) x = x + y * y;
4 fun void f(int z) let int x = 10; in g(z); end;
8 f(5);
```
g 호출 시 스택: [전역 영역 | f 프레임 | g 프레임]
1. 변수를 찾을 때 **맨 위 프레임**을 먼저 본다 → 있으면 지역 변수
2. 없으면 바로 아래 f 프레임이 아니라 **전역 변수 영역**을 본다
3. 그러려면 스택 안에서 프레임 영역과 전역 영역을 구분해야 한다

## 4. 컴파일러에서의 함수 구현
### 메모리 구조
| 영역 | 내용 |
|---|---|
| 레지스터 | PC(코드 위치), Frame Pointer(스택 위치) |
| 코드(텍스트) | 기계어 코드 |
| **실행시간 스택** | 지역 변수, 매개변수, 반환값, 복귀 주소 |
| **힙** | 동적 할당 (`malloc()`, `new`) |
| 데이터 | 정적·전역 변수 (`int maxcount = 99;`, `long sum[1000];`) |

### 제어 링크 vs 접근 링크 (중요)
| 링크 | 가리키는 곳 | 용도 |
|---|---|---|
| **제어 링크**(동적 링크) | **호출한** 함수의 활성 레코드 (바로 이전 레코드) | 반환 시 복귀 |
| **접근 링크**(정적 링크) | 피호출 함수가 **정의된** 블록/함수의 활성 레코드 | **비지역 변수** 접근 (정적 유효범위) |

함수 안에 함수를 정의할 수 있는 경우:
```
let int x=1;
    fun void g(int z) return x+z;
    fun void f(int y) let int x = 10; in return g(y) end
in f(3) end
```
g 의 x 는 접근 링크를 따라 바깥 블록의 x(=1) 를 찾는다 (f 의 x=10 이 아님).

### 변수 주소 계산
- **지역 변수**: `(fp) + offset` (그 함수가 실행 중이므로 fp 가 그 레코드를 가리킴)
- **비지역 변수**: 접근 링크를 따라간 레코드 주소 + 변수 x 의 상대 위치
- 따라갈 횟수 = **(x 를 사용하는 함수의 중첩 깊이) − (x 를 선언한 함수의 중첩 깊이)**
